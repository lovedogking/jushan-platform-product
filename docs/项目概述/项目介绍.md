---

## 1. 项目定位

智慧停车 SaaS 平台（jushan-platform）是停车业务的核心业务平台，负责多租户管理、停车场配置、设备台账、停车计费、支付、订单管理、月卡、优惠券等业务功能，并提供管理后台、岗亭端和微信小程序。

Device Access 是独立的外部服务，负责设备通信、协议适配和事件转换。双方通过共享契约协作。

---

## 2. 业务端组成

| 端 | 用途 | 技术形态 |
|---|---|---|
| admin-web | 平台总后台、客户运营端 | Vue 3 + Ant Design Vue |
| booth-web | 岗亭实时监控与人工兜底 | Vue 3 + Ant Design Vue |
| miniapp | 车主自助服务（绑定车牌、查费、缴费） | 原生微信小程序 |
| 后端服务 | 业务 API、设备调用、数据持久化 | Spring Boot 模块化单体 |

---

## 3. 当前阶段

M0（基线与冻结）→ M1+（工程骨架）。基础框架已搭建（多模块 Maven、Spring Boot 3、MyBatis-Plus、Sa-Token），业务模块正在逐步实现。

Device Access v0.4 已实现开闸、车牌识别事件推送（HTTP Webhook）、心跳、显示屏控制，一期可接入真实设备进行联调测试。

## 4. 第一阶段交付边界（一期 MVP）

### 4.1 已实现/部分实现

- 多租户创建与账号发放（由超级管理员统一创建租户和管理员账号，不支持自助注册）
- 公司/集团多级树形档案管理
- 管理员账号体系（三级）+ 自定义角色 + 细粒度权限矩阵
- 停车场、区域、车道、设备台账管理
- 收费规则引擎（按时/按次/阶梯/分时段）+ 版本管理与切换
- 车辆登记（免费车/固定车/储值车/VIP/超级车牌/黑名单）+ 一位多车
- 微信车主登录、车牌绑定、停车记录查询
- 车牌识别事件接收（HTTP Webhook）→ 入场停车记录（ParkingRecord + ParkingSession）
  - 开发阶段通过 Mock 事件模拟车牌识别流程；联调阶段切换为真实设备 Webhook 推送
- 岗亭监控大屏、交班记录、异常提醒
- P云聚合支付对接（被扫/预下单/回调/退款）
- 设备台账 → Device Access HTTP 调用（校时、状态查询、开闸、关闸、显示屏控制）+ 审计日志
- 授权码生成与激活
- 操作审计日志（全量配置变更记录）

### 4.2 一期明确不做（标注预留）

| 功能 | 原因 | 后续 |
|------|------|------|
| 设备心跳/在线状态实时监控（全自动） | 一期可用状态查询替代，心跳自动化待二期优化 | 二期优化 |
| 税控电子发票 | 需商务确认服务商 | 二期 |
| 充电优惠 | 明确二期模块（AGENTS.md §13.1） | 二期 S11-S18 |
| 多级审批流（会签/或签/转交） | 一期仅单级审批（通过/驳回） | 二期 |
| 硬件盒子车牌（蓝牙/NFC） | 一期仅纸质临时券 | 二期 |
| 数据开放平台 | 三期模块 | 三期 S19-S23 |
| 智能分析/经营看板 | 三期模块 | 三期 S19-S23 |

### 4.3 一期核心目标

一条标准车场可完成 **识别 → 计费 → 收费 → 放行** 闭环。
