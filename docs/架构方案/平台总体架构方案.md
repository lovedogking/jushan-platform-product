## 1. 项目定位

智慧停车 SaaS 平台（jushan-platform）是停车业务的核心业务平台，负责：

- 多租户管理、停车场配置、设备台账
- 停车计费、支付、订单管理
- 月卡、优惠券、预约等业务功能
- 管理后台、岗亭端、微信小程序
- 通过 Device Access 与现场设备交互

Device Access 是独立的外部服务，通过共享契约与 Platform 协作，负责设备通信、协议适配和事件转换。

### 4.3 关键依赖规则

- Controller → Application Service → Domain Service → Mapper → DB
- 模块间通过公开 Service/Facade 调用
- 禁止循环依赖
- 禁止支付模块调用 Device Access
- 禁止设备模块直接操作支付数据

## 5. Device Access 外部边界

### 5.1 当前能力（v0.2）

Device Access 当前仅提供 7 个 HTTP 端点：

1. POST /api/v1/devices — 创建设备
2. GET /api/v1/devices — 查询设备列表
3. GET /api/v1/devices/{deviceId} — 查询单个设备
4. PUT /api/v1/devices/{deviceId} — 更新设备
5. DELETE /api/v1/devices/{deviceId} — 删除设备
6. POST /api/v1/devices/{deviceId}/time/sync — 校时
7. GET /api/v1/devices/{deviceId}/status — 状态查询

当前: 无开闸、无车牌识别事件上报、无 RabbitMQ、无 HMAC 认证、无 commandId 幂等。

完整当前兼容契约见共享契约 `04-当前兼容契约-v0.2.md`。

### 5.2 目标能力（阶段 1）

参见共享契约 `05-目标契约-v1.0-草案.md`。

B01～B08 联合决策已 ACCEPTED（2026-07-11）。阶段 1 最小能力：

- PLATE_RECOGNIZED — 车牌识别事件
- OPEN_GATE — 开闸命令
- COMMAND_RESULT — 命令结果
- STATUS — 设备状态
- eventId / commandId / traceId
- Outbox / Inbox
- UNCERTAIN + 人工兜底 + 审计

暂缓: CLOSE_GATE、REBOOT、KEEP_OPEN、CANCEL_KEEP_OPEN、第二品牌、完整图片补传、完整离线运行。

### 5.3 Platform 职责

- 设备台账管理（主数据源）
- 设备 SN 可信映射
- 统一 DeviceAccessClient 调用
- 权限校验（租户、停车场、车道）
- 调用审计
- 不直接连接厂商设备
- 不解析厂商协议

## 6. 多租户与权限

- 所有数据操作必须带租户上下文
- 后端从可信上下文获取 tenantId，不信任前端传入
- 超级管理员代操作记录真实操作人
- 跨租户拒绝、跨停车场拒绝是 P0 级别

---

## 7. 数据库

- MySQL 8 + Flyway 版本迁移
- 新迁移文件使用新版本号，不修改已发布迁移
- 金额字段使用整数分或精确 Decimal
- 敏感信息不入库明文

---

## 8. 消息队列

- RabbitMQ 用于 Platform 内部业务事件
- 接收 Device Access 发布的统一业务事件（阶段 1 目标）
- 当前 Device Access 未发布事件（v0.2 事实）

---

## 9. 支付

- 金额使用整数分，禁止浮点数
- 支付回调验签（appid、mchid、outTradeNo、金额）
- 重复回调幂等
- 小程序返回不作为最终支付结果
- 支付成功与开闸解耦

---

## 10. 部署

- Docker Compose 本地开发
- 内网部署，Device Access 在同一内网
- 生产目标 HTTPS

---

## 11. 可观测性

- 结构化日志（SLF4J + Logback）
- 不记录密钥、密码、Token 等敏感信息
- 操作审计日志

---

## 12. 安全边界

- HMAC-SHA256 服务间认证（阶段 1 目标，B02 ACCEPTED）
- 当前 v0.2 Device Access 无服务间认证
- mTLS 暂缓（B02）
- Bearer Token 用于用户认证，不直接作为服务间认证方式
- 前端隐藏按钮不能代替后端鉴权

## 13. 构建与测试

### 13.1 构建命令

| 目标 | 命令 |
|------|------|
| 后端编译 | `mvn clean compile` |
| 后端测试 | `mvn test` |
| 后端打包（跳过测试） | `mvn clean package -DskipTests` |
| 集成测试 | `mvn verify` |
| 前端类型检查 | `npm run type-check` |
| 前端构建 | `npm run build` |

### 13.2 测试失败分类

1. 本轮回归 — 本次修改引起，必须修复
2. 既有失败 — 修改前已存在，记录不扩大
3. 环境阻塞 — 缺少外部依赖，标记和记录

### 13.3 Device Access 集成测试

Device Access 集成必须使用 HTTP Mock（WireMock 或等价工具），禁止用真机制造重复动作。

最低覆盖：HTTP 200 成功、404 设备不存在、503 MQTT 不可用、500 设备错误、命令超时、平台客户端超时、响应解析失败、跨停车场调用、重复调用、UNCERTAIN 状态、审计记录。
