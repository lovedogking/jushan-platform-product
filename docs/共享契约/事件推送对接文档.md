## 1. 推送方式

| 项目 | 说明 |
|------|------|
| 协议 | HTTP/1.1 POST |
| Content-Type | `application/json` |
| 编码 | UTF-8 |
| 目标地址 | 由业务侧提供，通过 `WEBHOOK_URL` 环境变量配置 |
| 推送时机 | 设备识别到车牌后实时推送（异步，不阻塞设备响应） |

---

## 2. 事件类型

当前仅支持 `PLATE_RECOGNIZED`（车牌识别事件）。

| 事件类型 | 说明 | 触发条件 |
|----------|------|----------|
| `PLATE_RECOGNIZED` | 车牌识别事件 | 相机设备识别到有效车牌后触发 |

---

## 4. 字段说明

### 4.1 信封字段

| 字段 | 类型 | 来源 | 必填 | 说明 |
|------|------|------|------|------|
| `eventId` | string | Device Access 生成 | 是 | UUID，唯一标识本次事件 |
| `eventType` | string | 固定值 | 是 | 目前只有 `PLATE_RECOGNIZED` |
| `tenantId` | string | 设备注册时传入 | 否 | 租户ID，未配置时不出现 |
| `parkingLotId` | string | 设备注册时传入 | 否 | 停车场ID，未配置时不出现 |
| `laneId` | string | 设备注册时传入 | 否 | 车道ID，未配置时不出现 |
| `platformDeviceId` | string | 设备注册时传入 | 否 | 业务侧设备标识，未配置时不出现 |
| `deviceSn` | string | 设备消息 | 是 | 设备序列号（厂商SN） |
| `vendor` | string | 产品目录 | 是 | 厂商：`ZHENSHI` / `XINLUTONG` |
| `occurredAt` | string | 设备消息 | 是 | 事件发生时间（ISO-8601，UTC） |
| `receivedAt` | string | Device Access | 是 | 收到时间（ISO-8601，UTC） |

### 4.2 Payload 字段

| 字段 | 类型 | 来源 | 必填 | 说明 |
|------|------|------|------|------|
| `payload.plateNo` | string | 设备消息 | 是 | 车牌号码 |
| `payload.plateColor` | integer | 设备消息 | 是 | 车牌颜色码：`1=蓝 2=黄 3=白 4=黑 5=绿` |
| `payload.confidence` | integer | 设备消息 | 是 | 置信度（0-100） |
| `payload.direction` | integer | 设备消息 | 是 | 方向：`1=入场 2=出场` |
| `payload.imagePath` | string | 设备消息 | 否 | 抓拍图片路径（设备本地路径） |

## 5. 重要约定

### 5.1 字段缺失 = 未配置

`tenantId` / `parkingLotId` / `laneId` / `platformDeviceId` 如果设备注册时没填，JSON 中**不会出现该字段**（不是 `null`）。业务侧用 `Optional` 或判断字段存在性即可。

### 5.2 幂等性（重要）

Device Access 采用"**最多一次**"语义：

- 推送成功（HTTP 2xx）即认为送达
- 网络失败或业务侧返回非 2xx 时，内存重试 3 次（间隔 5 秒）
- 全部失败后事件丢弃，不补发

**因此业务侧接口需要保证幂等**——用 `eventId` 作为唯一键去重，防止重复处理。

### 5.3 响应要求

业务侧返回 HTTP 2xx 即表示成功。响应体内容不解析，可以返回空或任意 JSON。

---

## 6. 业务侧需要提供

| 项目 | 说明 |
|------|------|
| Webhook URL | 接收事件推送的 HTTPS 端点 |
| 幂等保证 | 接口内部用 `eventId` 去重，同一事件多次推送只处理一次 |

---

## 7. 与 MQTT 事件总线的关系

本文档描述的 HTTP Webhook 推送是 Device Access 向平台推送事件的**直接通道**。在 MQTT 事件总线冻结并实施后，两者关系如下：

| 场景 | 通道 | 说明 |
|------|------|------|
| 平台未部署 MQTT 消费者 | HTTP Webhook | 作为降级/简化通道 |
| 平台已部署 MQTT 消费者 | MQTT 为主 | HTTP Webhook 可选保留作为冗余 |
| 关键事件可靠性要求高 | 双通道 | 平台需实现去重，同一事件可能从双通道到达 |

> **注意**：当前 v0.2 尚未提供 MQTT 事件发布能力，也未提供 HTTP Webhook 推送能力。本文档为预冻结设计，待 V01～V04 真机验证后确认字段和语义。

## 8. 平台侧代码修改建议

### 8.1 新增 Webhook 接收端点

当前平台通过 `RecognitionEventController`（`/api/v1/booth/recognition/handle`）接收模拟识别事件，该接口需要前端传入 `parkingLotId` 和 `laneId`。Device Access Webhook 推送的事件包含 `deviceSn`，平台应**从可信设备记录推导**租户、停车场和车道信息，禁止信任推送中的 `tenantId`/`parkingLotId`/`laneId`（即使存在）。

**建议新增 Controller**：

```java
package com.jushan.platform.modules.device.controller;

import com.jushan.common.R;
import com.jushan.platform.modules.device.dto.DeviceWebhookEvent;
import com.jushan.platform.modules.device.service.DeviceWebhookService;
import jakarta.validation.Valid;
import lombok.extern.slf4j.Slf4j;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * Device Access Webhook 接收控制器。
 * <p>
 * 接收设备推送的识别事件，处理幂等、设备身份校验后转发到业务层。
 * 注意：此接口<strong>不鉴权</strong>（Device Access 作为客户端调用），
 * 但需通过其他机制（如 IP 白名单、HMAC 签名）验证请求来源。
 */
@Slf4j
@RestController
@RequestMapping("/api/v1/device-webhook")
public class DeviceWebhookController {

    private final DeviceWebhookService webhookService;

    public DeviceWebhookController(DeviceWebhookService webhookService) {
        this.webhookService = webhookService;
    }

    /**
     * 接收车牌识别事件推送。
     * <p>
     * 返回 200 表示成功接收，Device Access 不再重试。
     * 业务处理异常应内部消化，不影响响应状态码。
     */
    @PostMapping("/events")
    public R<Void> receiveEvent(@Valid @RequestBody DeviceWebhookEvent event) {
        log.info("收到设备事件推送: eventId={}, eventType={}, deviceSn={}",
                event.getEventId(), event.getEventType(), event.getDeviceSn());
        webhookService.handleEvent(event);
        return R.ok();
    }
}
```

```java
package com.jushan.platform.modules.device.dto;

import com.fasterxml.jackson.annotation.JsonIgnoreProperties;
```

### 8.3 新增 Webhook 处理服务（核心安全逻辑）

```java
package com.jushan.platform.modules.device.service;

import com.jushan.common.BusinessException;
import com.jushan.common.CommonErrorCode;
import com.jushan.platform.modules.device.dto.DeviceWebhookEvent;
import com.jushan.platform.modules.booth.dto.RecognitionEventCmd;
import com.jushan.platform.modules.booth.service.RecognitionEventService;
import com.jushan.system.entity.Device;
import com.jushan.system.mapper.DeviceMapper;
import com.jushan.system.event.RecognitionEventPayload;
import lombok.extern.slf4j.Slf4j;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

import java.time.LocalDateTime;
import java.time.ZoneId;

/**
 * Device Access Webhook 处理服务。
 * <p>
 * <strong>安全约束</strong>：
 * <ul>
 *   <li>禁止信任推送中的 tenantId/parkingLotId/laneId，必须从可信设备记录推导</li>
 *   <li>deviceSn 必须在平台设备台账中存在且启用</li>
 *   <li>eventId 必须幂等，重复事件返回已处理结果</li>
 *   <li>direction 必须与设备绑定的车道方向一致</li>
 * </ul>
 */
@Slf4j
@Service
public class DeviceWebhookService {

    private final DeviceMapper deviceMapper;
    private final RecognitionEventService recognitionEventService;
    // TODO: 注入幂等缓存（Redis）
    // private final StringRedisTemplate redisTemplate;

    public DeviceWebhookService(DeviceMapper deviceMapper,
                                RecognitionEventService recognitionEventService) {
        this.deviceMapper = deviceMapper;
        this.recognitionEventService = recognitionEventService;
    }

    @Transactional(rollbackFor = Exception.class)
    public void handleEvent(DeviceWebhookEvent event) {
        // 1. 幂等校验：用 eventId 去重
        // TODO: 实现 Redis 幂等检查
        // String idempotencyKey = "webhook:event:" + event.getEventId();
        // if (redisTemplate.hasKey(idempotencyKey)) {
        //     log.info("事件已处理，跳过: eventId={}", event.getEventId());
        //     return;
        // }

        // 2. 从 deviceSn 查询可信设备记录
        Device device = deviceMapper.selectByDeviceSn(event.getDeviceSn());
        if (device == null) {
            log.error("设备不存在: deviceSn={}", event.getDeviceSn());
            throw new BusinessException(CommonErrorCode.BUSINESS_ERROR,
                    "设备不存在: " + event.getDeviceSn());
        }

        if (!"ENABLED".equals(device.getStatus())) {
            log.error("设备已停用: deviceSn={}, deviceId={}", event.getDeviceSn(), device.getId());
            throw new BusinessException(CommonErrorCode.BUSINESS_ERROR,
                    "设备已停用: " + event.getDeviceSn());
        }

        // 3. 校验设备类型（必须是 CAMERA）
        if (!"CAMERA".equals(device.getDeviceType())) {
            log.error("非相机设备推送了识别事件: deviceSn={}, type={}",
                    event.getDeviceSn(), device.getDeviceType());
            throw new BusinessException(CommonErrorCode.BUSINESS_ERROR,
                    "非相机设备不能推送识别事件");
        }

        // 4. 校验方向与车道一致性
        // TODO: 从 lane 表查询车道方向，校验 event.direction 是否匹配

        // 5. 转换为平台内部 RecognitionEventPayload
        RecognitionEventPayload payload = new RecognitionEventPayload();
        payload.setEventId(event.getEventId()); // 使用 Device Access 的 eventId 作为幂等键
        payload.setVendorEventId(event.getEventId());
        payload.setDeviceId(device.getId());
        payload.setLaneId(device.getLaneId());
        payload.setParkingLotId(device.getParkingLotId());
        payload.setTenantId(device.getTenantId());
        payload.setPlateNumber(event.getPayload().getPlateNo().toUpperCase());
        payload.setDirection(event.getPayload().getDirection() == 1 ? "ENTRY" : "EXIT");
        payload.setEventTime(LocalDateTime.ofInstant(event.getOccurredAt(), ZoneId.systemDefault()));
        payload.setImagePath(event.getPayload().getImagePath());
        payload.setConfidence(event.getPayload().getConfidence());
        payload.setSource("DEVICE_ACCESS");
        payload.setRawData(event.toString()); // 调试用，生产可裁剪

        // 6. 转换为 RecognitionEventCmd 调用现有业务逻辑
        RecognitionEventCmd cmd = new RecognitionEventCmd();
        cmd.setParkingLotId(device.getParkingLotId());
        cmd.setLaneId(device.getLaneId());
        cmd.setPlateNumber(payload.getPlateNumber());
        cmd.setPlateColor(String.valueOf(event.getPayload().getPlateColor()));
        cmd.setDirection(payload.getDirection());
        cmd.setCaptureImage(payload.getImagePath());
        cmd.setConfidence(event.getPayload().getConfidence());

        // 7. 调用业务处理
        recognitionEventService.handleEvent(cmd);

        // 8. 标记幂等键已处理
        // TODO: redisTemplate.opsForValue().set(idempotencyKey, "1", Duration.ofHours(24));

        log.info("设备事件处理完成: eventId={}, plate={}, direction={}",
                event.getEventId(), payload.getPlateNumber(), payload.getDirection());
    }
}
```

### 8.5 幂等实现建议

使用 Redis 实现 24 小时幂等窗口：

```java
// 在 DeviceWebhookService 中注入
private final StringRedisTemplate redisTemplate;

// 幂等检查
String idempotencyKey = "webhook:event:" + event.getEventId();
Boolean exists = redisTemplate.hasKey(idempotencyKey);
if (Boolean.TRUE.equals(exists)) {
    log.info("事件已处理，跳过: eventId={}", event.getEventId());
    return;
}

// 处理完成后标记
redisTemplate.opsForValue().set(idempotencyKey, "1", Duration.ofHours(24));
```

### 8.6 方向校验建议

```java
// 在 ParkingLane 实体或查询中增加方向字段

ParkingLane lane = laneMapper.selectById(device.getLaneId());

    String expectedDirection = event.getPayload().getDirection() == 1 ? "ENTRY" : "EXIT";
    if (!expectedDirection.equals(lane.getDirection())) {
        log.error("方向不匹配: deviceSn={}, eventDirection={}, laneDirection={}",
                event.getDeviceSn(), expectedDirection, lane.getDirection());
        throw new BusinessException(CommonErrorCode.BUSINESS_ERROR, "方向不匹配");
    }
}
```
