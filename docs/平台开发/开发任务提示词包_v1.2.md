## 任务包 0-2：Webhook 签名校验

```
【任务包 0-2】设备 Webhook 增加 HMAC 签名校验（SEC-005 / COMM-002）

需求依据：V1.1 3.4.2（COMM-002 签名校验防伪造）、4.2 SEC-005

背景：SecurityConfig 第 57 行 /api/v1/device-webhook/** 全量 permitAll，
DeviceWebhookController/Service 无任何签名验证，任何人可伪造识别事件。
现有可选 IP 白名单（device-access.webhook.allowed-ips，默认 * 全放行），
不能替代签名。

目标：
1. 平台侧为每个适配器实例（或每个车场）配置 webhookSecret
   （sys_config 或独立表，配置化，不入库明文硬编码）；
   同步收紧 IP 白名单默认值（生产环境禁止 *，启动校验告警）
2. 约定签名算法：HMAC-SHA256(secret, timestamp + nonce + rawBody)，
   请求头携带 X-Sign / X-Timestamp / X-Nonce；平台校验签名与
   时间戳偏差（±5 分钟）与 nonce 防重放（Redis SETNX，TTL 10 分钟）
3. 校验失败返回 401 并记安全日志；校验逻辑做成独立 Filter/拦截器，
   不影响 DeviceWebhookService 现有业务（台账校验/幂等/方向推断保留）
4. SecurityConfig 保留 permitAll（适配器无 JWT），但 Filter 必须在
   业务 Controller 之前强制验签
5. 编写验签测试工具：一个可生成合法签名请求的脚本/测试类，
   供适配器侧对接（输出到 docs/ 说明签名规范）

约束：
- 与适配器侧的签名规范必须写成文档（docs/设备接入/webhook签名规范.md），
  作为双方契约
- 验签失败不返回具体原因细节（防探测），仅 401
- 现有内存幂等保留，多实例 Redis 幂等升级在本包一并完成
  （eventId Redis SETNX + TTL 24h，替换内存 Map）

验收标准：
1. 无签名/错误签名/过期时间戳/重放 nonce 四种请求均被拒（测试覆盖）
2. 合法签名请求正常处理，识别事件主链路不受影响
3. 多实例幂等：两个节点同时收到同一 eventId 只处理一次（可用
  集成测试模拟）
4. 签名规范文档输出到 docs/
```

## 任务包 0-3：设备模型解锁双相机与识别方向

```
【任务包 0-3】设备/车道模型扩展：识别方向 + 主备关系 + 解除一车道一相机限制

需求依据：V1.1 3.1.4（ADMIN-004 双向通道）、3.1.5（ADMIN-005 主备/识别方向）、

1. Flyway 新脚本：DROP uq_lane_device_type 唯一索引（保留普通索引）
2. device 表新增字段：recognition_direction TINYINT（1=入场/2=出场，

   的逻辑升级为优先按相机 recognition_direction 判定（兼容臻识
   direction=4 的推断逻辑保留为兜底）
5. 主备切换：识别事件默认消费主相机；主相机离线（设备状态快照/告警
   驱动）时自动切备相机，切换记日志+MonitorAlert 告警；加 60 秒防抖
   （切换冷却期内不反复切换）
6. 运营端设备管理页：表单增加识别方向、主备关系字段；双向通道的
   绑定完整性在界面可感知

约束：
- 存量单向通道数据不受影响（迁移脚本对存量数据 direction 按车道
  类型回填：入口车道=1，出口车道=2，双向=NULL 需人工补录并输出清单）
- 主备切换不改动开闸执行设备（executor_device_id）逻辑

验收标准：
1. 双相机主备绑定、双向通道双方向绑定可保存；缺方向/缺主备被拦截
2. 识别事件按相机方向正确生成入场/出场记录（Mock 事件验证双向通道）
3. 主相机离线自动切备相机（模拟离线事件验证），防抖生效
4. 存量数据回填脚本执行后无 NULL direction 的单向车道相机
```

```

5. 模拟退款：运营端对 PAID 订单发起退款——必填退款原因，状态置

   弹窗填原因）、订单详情展示状态流转日志与退款信息

约束：
- 存量 PENDING_PAY/PAID 订单不受影响（无需数据订正，说明理由）
- 月卡/固定车位/白名单车辆入场不生成订单的口径全链路一致

## 任务包 1-3：计费规则收敛与生效方式对齐

```
【任务包 1-3】计费体系统一：以 billing_rule 为唯一，补齐 V1.1 生效方式

需求依据：V1.1 3.1.10（ADMIN-010）、7.1、确认项 34

背景：任务包 0-1 已冻结新 fee_rule 体系。旧 BillingEngine 已支持：
免费时长、首时段+后续单位时段、单日封顶 dailyCap、最大封顶 maxAmount、

差距：V1.1 三种生效方式（立即生效/仅新入场生效/定时生效）未完整落地。

目标：
1. billing_rule 增加 effect_type（IMMEDIATE/NEW_ENTRY_ONLY/SCHEDULED）
   与 effect_time（定时生效时间）字段（Flyway）

【任务包 7-1】拆除平台直连 EMQX，GPIO 收敛至适配器；出站命令幂等重试 + MQTTS 安全

需求依据：V1.2 2.3.2（废止平台直连 EMQX 过渡方案）、3.4.1（COMM-001
幂等+重试 3 次，适配器同机内网回环）、3.4.3（COMM-003 EMQX 云端部署 +
MQTTS）、4.2 SEC-012（设备级 ACL）、确认项 62

背景：GpioGateService 平台直连 EMQX 开闸（broker 地址硬编码
tcp://121.41.131.215:1883），违反 V1.2 架构决策。DeviceAccessClient
开闸调用无 commandId 幂等与重试。V1.2 明确：适配器与平台同机云端部署
（内网回环 127.0.0.1），EMQX 云端部署仅对公网开放 MQTTS 8883 端口。

目标：
1. 拆除 GpioGateService 直连 EMQX 通道：开闸/关闸全部改走
   DeviceAccessClient（平台→适配器 HTTP 内网回环）；识别事件的开闸回退链
   （GATE→CAMERA+OPEN_GATE→车场级相机 GPIO）同步改为向适配器
   下发（适配器侧负责 MQTT 到设备）
2. EMQX 连接配置从平台配置中移除（或标注仅适配器使用）；硬编码
   broker 地址清除
3. DeviceAccessClient 增加：commandId 幂等键（UUID，命令审计落库
   device_command_audit 关联）、无响应重试 3 次（间隔可配置，
   默认 1s/5s/30s）、最终失败告警（MonitorAlert）
4. 适配器未就绪环境：Mock 适配器开关（配置化，local/test profile
   默认开），保证开闸链路可自验；注意 DEV profile 下适配器 URL 走
   127.0.0.1（同机内网回环）
5. REL-006 白名单同步出口：平台提供"月卡/固定车位/白名单车牌"
   增量同步接口（适配器经云端 MQTT 定期同步至相机本地白名单），字段与
   频率写入契约文档
6. EMQX MQTTS 安全落实（运维/部署任务）：云端 EMQX 仅开放 8883 端口
   （MQTTS），必须启用 TLS 加密 + 设备级 ACL（每台相机仅可收发自身
   Topic），并按 SEC-012 要求配置用户名密码认证
7. PDNS 云平台备选通路（非本期主路径，仅记录方案）：臻识 C5 SDK
   支持通过 PDNS 云平台（open.vzicloud.com）注册设备并中继通信；
   当适配器链路不可用时（适配器宕机/内网通信异常），可在适配器中
   预留 PDNS fallback 接口（`ConvertPDNSNetworkParam` 转换云平台
   IP→设备真实IP），供现场应急使用；本期不做对接，仅记录方案

约束：
- 控制链路单一：平台任何代码不得直连 EMQX（全局搜索验证）
- 命令审计完整（commandId/设备/命令/结果/耗时）
- 平台↔适配器为内网回环通信（127.0.0.1），禁止配置公网地址

验收标准：
1. 全库无平台侧 EMQX 连接（grep 验证）
2. 开闸命令带 commandId，重试 3 次后告警（故障注入测试）
3. Mock 适配器下开闸全链路自验通过
4. 白名单同步接口可用，契约文档更新

## 任务包 7-2：云端流媒体网关与 GB28181 视频预览

```
【任务包 7-2】云端流媒体网关部署 + 相机 GB28181 推流 + 岗亭端 WebRTC 视频预览

需求依据：V1.2 2.3.2、3.2.3（BOOTH-003）、5.2、COMP-007、PERF-006、
SEC-012（公网端口收敛）

背景：视频链路完全空白。V1.2 修订架构：现场无边缘设备，相机仅经路由器
NAT 上网。流媒体网关云端部署，相机通过 GB28181 主动注册并推流至云端
（穿透 NAT），由网关转封装为 WebRTC 供岗亭端浏览器播放（≤500ms）。
选型示例：WVP-GB28181 + ZLMediaKit。

**重要前置确认**：臻识 C5/C5H SDK **不支持 P2P 直连**，P2P 视频通道
不可用。视频方案只有 GB28181 一条路径（或降级方案中的 RTSP 拉流），
不存在"用 P2P 替代 GB28181"的选项。

目标：
1. 网关选型与部署：选型 WVP-GB28181 + ZLMediaKit（或 SRS），
   Docker Compose 部署配置并入云端服务器；明确对外端口（仅集群内/
   专线可访，不暴露公网新增端口，WebRTC 走已有 WSS 反向代理或
   内网回环）
2. GB28181 相机注册配置：每台相机在流媒体网关注册（设备ID + 密码 +
   SIP 服务器指向云端流媒体网关 IP），确认相机须支持 GB28181 主动推流
   （设备选型/施工前必须确认，见 BOOTH-003 前提）
3. 降级方案（BOOTH-003）：对不支持 GB28181 的已采购相机，提供
   二选一降级方案说明并记录到部署文档——① 车场路由器端口映射（须公网
   IP，施工前逐车场确认）；② 现场增设低成本边缘盒子运行流媒体网关
   （仅该车场适用，回到现场拉 RTSP 方案）
4. 播放地址管理：车场/通道与 GB28181 设备通道/WebRTC 播放地址的
   映射配置（车场级配置或设备扩展字段），播放地址带鉴权（防裸奔）
5. 岗亭端视频组件：WebRTC 播放器接入（接入任务包 4-3 的视频占位区），
   单相机单画面、双相机主备双画面；相机离线显示离线提示
6. 输出部署文档：docs/部署运维/流媒体网关部署.md（含 WVP-GB28181
   配置、相机 GB28181 注册参数模板、WebRTC 播放地址生成规则、
   降级方案说明）；视频延迟监控方案（≤500ms 验证方法，以现场上行
   带宽 ≥ 2Mbps/路为前提）

约束：
- 流媒体网关云端部署，相机经公网 GB28181 主动推流（穿透 NAT），
  现场无需边缘设备或公网 IP
- 公网端口收敛：WebRTC 流量走已有 443 端口（WSS 隧道或反向代理），
  不新增公网暴露端口；GB28181 推流端口仅对相机 IP 段开放
- 无真实相机时用 GB28181 模拟器或公开 WebRTC 测试流验证
- 相机须支持 GB28181，须在设备选型/施工前逐型号确认，不支持则按
  降级方案处理

验收标准：
1. GB28181 模拟器推流经云端网关转封装后岗亭端浏览器可播放
2. 模拟网络延迟 ≤500ms（以带宽正常为前提）
3. 部署文档可复现，含降级方案说明
4. 播放地址鉴权生效，裸 URL 不可播放
```
