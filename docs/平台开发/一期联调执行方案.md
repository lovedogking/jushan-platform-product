## 一、联调整体策略

### 1.1 核心原则

- **Mock 先行，真机后补**：所有业务链路先以 Mock 适配器跑通，真机到位后再切换验证
- **先通后优**：P0 阻塞项全部通过再进入设备联调，P1 项联调期间并行优化
- **每个剧本覆盖至少一条异常分支**

### 1.2 联调阶段划分


| 阶段       | 周期    | 目标                   |
| -------- | ----- | -------------------- |
| **联调前**  | 1-2 天 | P0 阻塞项全量通过，环境就绪      |
| **联调期间** | 2-3 周 | 10 个全流程剧本逐条执行，设备接入验证 |
| **联调后**  | 1 天   | 技术债务评审，输出验收报告        |


### 1.3 环境要求


| 组件           | 要求                                             |
| ------------ | ---------------------------------------------- |
| 后端           | `parking-boot` 启动无 ERROR，Actuator readiness UP |
| 前端 admin-web | `pnpm dev` 可访问登录页                              |
| 前端 booth-web | `pnpm dev` 可访问监控页                              |
| 中间件          | MySQL / Redis / RabbitMQ 健康检查通过                |
| 数据库          | Flyway 所有迁移脚本执行成功                              |
| 适配器          | Mock 模式（`pyun.mock=true`），URL 走 `127.0.0.1`    |

## 二、联调前：P0 阻塞项逐项检查

> **任一 P0 项未通过，禁止进入设备联调。**



### 2.1 基础设施启动

- [ ] `docker-compose up` 成功，MySQL/Redis/RabbitMQ 健康检查通过
- [ ] `parking-boot` 无 ERROR 日志，Actuator readiness 返回 UP
- [ ] admin-web `pnpm dev` 成功，登录页可访问
- [ ] booth-web `pnpm dev` 成功，监控页可访问
- [ ] Flyway 所有脚本执行成功，无重复执行错误



### 2.2 多租户与权限

- [ ] 超管创建租户管理员：超管直接录入租户管理员账号/密码（无需自助注册审核流程）
- [ ] 超管创建岗亭管理员：超管直接录入岗亭管理员账号/密码，分配跨租户停车场
- [ ] 租户数据隔离：租户 A 管理员无法查看租户 B 数据（SQL 拦截验证）**🔴 红线**（岗亭管理员不受此限制）
- [ ] 岗亭管理员跨租户：岗亭管理员可查看被分配的所有停车场（可来自不同租户）**🔴 红线**
- [ ] RBAC 权限控制：角色可分配菜单/按钮权限，无权访问返回 403
- [ ] 登录限流：连续失败 5 次锁定 15 分钟，Redis 记录可验证
- [ ] 岗亭停车场分配：超管可将任意租户的停车场分配给岗亭管理员（`sys_admin_account_parking_lot`）



### 2.3 停车场与设备台账

- [ ] 停车场 CRUD：租户内可创建/编辑/查询/启用停用停车场
- [ ] 车道管理：可配置入口/出口方向，方向枚举校验有效
- [ ] 设备台账：可绑定设备到停车场+车道，记录厂商 SN
- [ ] 设备方向校验：入口设备只能用于入场事件，否则失败关闭 **🔴 红线**
- [ ] Device Access 调用：校时、状态查询 HTTP 调用成功，记录审计日志



### 2.4 车辆入场与停车记录

- [ ] Mock 识别事件：模拟车牌识别 → 创建停车记录，状态为 ENTERED
- [ ] 重复入场策略：同一车牌在场时，重复入场返回已有记录（不重复创建）
- [ ] 车牌标准化：入库前转大写，查询匹配不区分大小写
- [ ] 停车场容量联动：入场成功剩余车位 -1，出场成功 +1，不为负



### 2.5 计费引擎

- [ ] 按时长计费：配置阶梯费率，计算结果与手工核对一致
- [ ] 固定金额计费：配置固定金额，任意时长费用一致
- [ ] 免费规则：配置免费时段，费用为 0
- [ ] 金额精度：所有计算使用 BigDecimal，无浮点数参与 **🔴 红线**
- [ ] 收费规则版本：可切换生效版本，历史版本保留只读



### 2.6 订单与支付（Mock 阶段）

- [ ] 订单生成：出场时生成订单，金额与计费引擎一致
- [ ] 支付下单：Mock 支付返回支付参数
- [ ] 支付回调：Mock 回调 → 订单状态更新为已支付
- [ ] 回调幂等：同一回调重复发送，订单不重复更新 **🔴 红线**
- [ ] 回调验签：签名错误/金额不符/订单号不匹配 → 标记异常 **🔴 红线**



### 2.7 出场与放行

- [ ] 出场匹配：车牌识别 → 匹配在场记录，计算费用
- [ ] 已支付放行：支付成功 → 允许出场，状态变为 EXITED
- [ ] 免费放行：费用为 0 → 直接放行，记录免费原因
- [ ] 人工放行：岗亭端可人工触发，记录操作人和原因
- [ ] 状态机校验：非法状态迁移（如未支付直接出场）→ 拒绝 **🔴 红线**



### 2.8 岗亭端实时推送

- [ ] WebSocket 连接：STOMP 连接成功，订阅停车场频道
- [ ] 入场事件推送：识别事件 → 岗亭端实时显示车牌、时间
- [ ] 支付成功推送：支付回调 → 岗亭端显示"已支付，请放行"
- [ ] 异常提醒：设备离线/识别失败 → 岗亭端弹窗提醒

## 五、联调后：收尾动作

1. **输出《联调验收报告.md》**：每个剧本的通过/失败结论、证据附件、失败项修复任务建议
2. **召开技术债务评审会**：按 P0/P1/P2 优先级将遗留问题纳入二期计划
3. **监控数据收集**：缓存命中率、MQ 流量、模块构建耗时（联调期间持续采集）
4. **签字结项**：后端/前端/测试/技术负责人四方签字
