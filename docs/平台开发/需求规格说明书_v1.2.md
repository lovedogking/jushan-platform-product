## 1. 引言

### 1.1 编写目的

本文档为停车SaaS系统的需求规格说明书（SRS），旨在明确系统功能边界、业务流程、数据规则及非功能约束，作为产品、开发、测试团队后续工作的统一依据。本文档基于85项需求确认问答整理，所有功能点均已与产品方确认。V1.1 版本在 V1.0 基础上完成全面审查修订，消除内部矛盾、补齐流程漏洞、明确技术方案；V1.2 版本依据车场现场实际条件（无边缘设备、相机纯网线上网）完成部署架构修订。

### 1.2 项目背景

建设一套面向多租户、多车场的停车SaaS管理系统，支持运营端集中管理、岗亭端现场作业、小程序端车主自助服务，并通过适配器层对接各类停车场硬件设备（相机、道闸等）。

### 1.3 术语定义

| 术语 | 英文 | 定义 |
| :--- | :--- | :--- |
| SaaS | Software as a Service | 软件即服务，本系统以多租户模式向多个停车场提供服务 |

## 2. 系统概述

### 2.1 系统目标

1. 为停车场运营方提供一套可配置、可扩展的SaaS化管理平台；
2. 支持一个运营平台管理多个租户、多个车场；
3. 通过适配器层解耦平台与硬件设备，便于后续接入不同品牌设备；
4. 为车主提供便捷的自助缴费、月卡办理、余位查询等服务；
5. 为现场管理人员提供实时监控、通行作业、收费处理、交接班等工具。

### 2.2 系统范围

**本期包含：**
- 运营端Web管理后台（车场运营、车辆管理、收费管理、通行记录、数据报表、系统管理）
- 岗亭端Web操作终端（实时监控、通行作业、收费处理、交接班）
- 小程序端车主服务（停车缴费、月卡服务、固定车位、车辆管理、余位查询）
- 平台-适配器-设备通信框架（HTTP REST + Webhook + MQTT）
- 模拟支付全流程

**本期不包含：**
- 优惠券/会员积分系统
- 访客预约管理
- 商家优惠/商家减免
- 真实支付渠道对接（微信支付、支付宝等）
- 电子发票真实开具
- 寻车导航
- 短信推送（手机号绑定采用微信「手机号快速验证」组件，不依赖短信）
- 岗亭端断网离线操作（以相机本地白名单现场降级替代，见 REL-006）
- 车位地感/检测器硬件对接
- 支付宝小程序（远期评估）

**部署形态说明（V1.2 修订）：**
- 现场实际条件为**无工控机等边缘设备，相机经纯网线（路由器NAT）上网**，故平台服务层、适配器层、EMQX、流媒体网关及数据库等基础设施**全部部署于同一台云端服务器**；
- 平台 ↔ 适配器同机通信，走内网回环（127.0.0.1），适配器接口**不暴露公网**；
- 相机作为 MQTT Client **主动外连**云端 EMQX（穿透NAT，无需现场具备公网IP），接收控制指令并上报状态；
- 相机通过 **GB28181 主动推流**至云端流媒体网关，转封装为 WebRTC 供岗亭端浏览器播放；
- 公网暴露端口收敛为 **443（HTTPS/WSS）与 8883（MQTTS）** 两个，其余服务仅监听内网。

#### 2.3.2 通信架构说明

| 方向 | 协议 | 用途 | 说明 |
| :--- | :--- | :--- | :--- |
| 平台 → 适配器 | HTTP REST | 命令下发 | 设备注册、查询、开闸、关闸、校时、状态查询共6个端点。**适配器与平台同机部署，走内网回环调用，不暴露公网（V1.2 修订，废止原"适配器须公网可达、施工方打通网络"前提）** |
| 适配器 → 平台 | HTTP Webhook | 事件上报 | 识别事件、设备状态变化等实时推送，签名校验 |
| 适配器 → 设备 | MQTT | 设备控制 | 通过 EMQX Broker 与相机/道闸通信 |
| 平台 → 岗亭端 | WebSocket | 实时通知 | 远程开闸弹窗、设备告警、重复入场等实时推送 |
| 岗亭端 → 流媒体网关 | WebRTC | 视频预览 | 相机GB28181主动推流至云端流媒体网关，转封装为WebRTC后播放 |
| 相机GPIO控制 | HTTP REST → MQTT | 开闸/关闸 | 统一经"平台→适配器→MQTT→设备"链路，平台不直连EMQX |

**架构选型理由：**
- 不采用 MQTT 作为平台↔适配器主通信：平台作为 MQTT client 会增加认证、Topic管理、重连逻辑复杂度。
- 不采用 WebSocket 作为平台↔适配器通信：虽适合实时推送，但命令下发和事件上报的协议精度不如 REST + Webhook 清晰（幂等、重试、鉴权更简单）。WebSocket 仅用于平台→岗亭端的浏览器实时推送。
- **V1.1 变更：废止 v0.2 联调阶段"平台直连 EMQX 控制相机 GPIO"的过渡方案**。GPIO 控制指令统一经适配器转发，保证控制链路单一、设备协议差异全部封装在适配器内，避免多品牌接入时出现第二条控制通道。
- 相机RTSP流浏览器无法原生播放，且相机位于车场内网（NAT后）、现场无边缘设备，云端无法主动拉流，故采用**相机GB28181主动注册推流**方案：相机推流至云端流媒体网关（WVP-GB28181 + ZLMediaKit），转封装为WebRTC供岗亭端播放，满足 ≤500ms 延迟指标（V1.2 修订，替代原"现场部署流媒体网关拉RTSP"方案；相机须支持GB28181，须在设备选型/施工前确认，降级方案见 BOOTH-003）。
- 当前 v0.2 架构已通过臻识 C5H 真机联调验证。

### 2.4 角色定义

#### 2.4.1 角色总览

| 角色 | 定位 | 创建方式 | 使用终端 |
| :--- | :--- | :--- | :--- |
| 超级管理员 | 平台级最高权限 | 系统预设 | 运营端 |
| 租户管理员 | 车场/租户级管理 | 仅超级管理员创建 | 运营端 |
| 岗亭管理员 | 现场级操作 | 仅超级管理员创建并分配车场 | 岗亭端 |
| 小程序用户 | C端车主 | 微信授权+手机号快速验证绑定 | 小程序端 |

#### 2.4.2 超级管理员

- **职责**：全平台数据可见、可创建并管理租户管理员和岗亭管理员、可配置角色权限矩阵、可远程开闸、可配置所有系统参数。
- **权限范围**：全平台所有车场、所有模块。
- **特殊权限**：账号管理、角色权限配置、系统参数配置、远程开闸（全通道）。

#### 2.4.3 租户管理员

- **职责**：管理被分配的车场（一对多）、配置收费规则、管理车辆、查看订单和报表。
- **权限范围**：只能看到被分配车场的数据，超级管理员可配置其可见范围（部分车场/全部车场）；车场的新建与删除仅超级管理员可执行，租户管理员可查看/修改被分配车场。
- **特殊权限**：远程开闸权限由超级管理员单独配置（默认关闭）。

#### 2.4.4 岗亭管理员

- **职责**：管理被分配的多个车场（左侧车场列表切换）、实时监控、通行作业、现场收费、交接班。
- **权限范围**：只能看到所管理车场的数据。
- **归属说明**：岗亭管理员不隶属于特定租户，可由超级管理员分配全平台任意车场；其数据可见范围严格限于被分配的车场，不构成对租户数据隔离（SEC-007）的越权。
- **特殊权限**：费用减免权限需超级管理员在创建账号时勾选"允许减免"。

#### 2.4.5 小程序用户

- **职责**：自助停车缴费、月卡办理、余位查询、代缴停车费。
- **权限范围**：无后台管理权限，仅操作与自身车辆相关的功能。
- **准入条件**：微信授权登录后，须通过微信「手机号快速验证」组件绑定手机号（用户点击授权即可完成，无需短信验证码），否则不可使用核心功能。

#### 3.1.2 车场管理

**功能编号**：ADMIN-002  
**功能名称**：车场基础信息管理与车场级参数配置  
**功能描述**：对车场的基础信息进行配置和状态管理，并维护该车场的差异化业务参数。  
**前置条件**：新建/删除车场仅超级管理员；租户管理员可查看/修改被分配车场。  
**输入**：
- 车场名称（必填）
- 车场地址（必填）
- 总车位数（必填，正整数）
- 联系人/联系电话（选填）
- 状态：启用/停用
- 车场级参数（见业务规则）  
**处理流程**：
1. 用户填写车场信息并提交；
2. 系统校验总车位数为正整数；
3. 保存车场信息，生成车场ID。  
**输出**：车场列表（支持分页、搜索、筛选、排序）。  
**异常处理**：
- 总车位数非法：提示"总车位数必须为正整数"。  
**业务规则**：
- 停用车场后，该车场不再接收新订单，但历史数据仍可查询；
- 一个租户可管理多个车场（一对多）；
- **车场级参数统一在车场设置中维护**（全局参数见 ADMIN-020），包括：

| 参数 | 默认值 | 说明 |
| :--- | :--- | :--- |
| 模拟支付超时时间 | 15分钟 | 待支付订单超时可自动关闭 |
| 未支付出场策略 | 拦截 | 拦截不开闸 / 允许欠费出场 |
| 欠费车辆再次出场策略 | 必须补缴 | 必须补缴欠费后放行 / 仅提醒 |
| 识别失败处理策略 | 转人工处理 | 转人工处理 / 自动放行 |
| 月卡到期提醒天数 | 7天 | 本期仅系统记录与预警列表，不推送 |
| 月卡/固定车位是否计入余位 | 计入 | 影响余位计算口径 |
| 支付后出场窗口期 | 15分钟 | 提前缴费后允许自动开闸出场的有效时长 |

#### 3.1.3 区域/车位管理

**功能编号**：ADMIN-003  
**功能名称**：区域划分与车位管理  
**功能描述**：将车场划分为多个区域，配置各区域车位数；管理固定车位绑定。  
**前置条件**：车场已创建。  
**输入**：
- 区域名称（必填）
- 区域车位数（必填）
- 固定车位号（如启用固定车位功能）
- 固定车位绑定车辆（车牌号）  
**处理流程**：
1. 用户创建区域，分配车位数；
2. 系统校验各区域车位数之和 ≤ 车场总车位数；
3. 固定车位需绑定具体车位号和车辆。  
**输出**：区域列表、固定车位列表。  
**业务规则**：
- 固定车位绑定具体车位号，该车位专属此车；
- **系统仅记录固定车位绑定关系，不校验车位的实际物理占用**（防止他车占用依赖现场管理）；
- 本期一个固定车位绑定一辆车（1:1）；一位多车（多车共享一个固定车位）列入二期评估；
- 月卡不绑定车位号，仅保证入场权限。

**功能名称**：出入口通道配置  
**功能描述**：配置车场的出入口通道基本信息及通行方向。

- 通道类型：入口 / 出口 / 双向通行（必填）

1. 用户创建通道并配置类型；
2. 系统保存通道信息。

**业务规则**：
- 通道类型支持双向通行，同一通道既可进也可出；

#### 3.1.5 设备管理

**功能编号**：ADMIN-005  
**功能名称**：出入口相机绑定与管理  
**功能描述**：对出入口相机进行绑定、解绑、配置主备关系、远程校时、状态监控。  
**前置条件**：通道已创建。  
**输入**：
- 相机IP地址（必填）
- 端口号（必填）
- 用户名/密码（必填）
- 所属车场（自动关联）
- 所属通道（必填）
- 相机编号/名称（必填）
- 主备关系：主相机 / 备相机（双相机模式时配置）
- 识别方向：入场 / 出场（双向通道时必填）  
**处理流程**：
1. 用户填写相机信息并绑定到通道；
2. 系统校验IP格式和端口合法性；
3. 保存相机信息，尝试连接测试；
4. 支持远程校时（平台 HTTP REST → 适配器 → 设备）。  
**输出**：设备列表（含在线/离线状态）。  
**异常处理**：
- 相机连接失败：标记为离线，触发告警。  
**业务规则**：
- 必须支持单相机模式和双相机模式；
- 双相机模式需指定主备关系，主相机故障时自动切换备相机；
- 设备离线时运营端弹窗告警，同时岗亭端弹窗提示（经WebSocket实时推送）。

#### 3.1.6 月卡管理

**功能编号**：ADMIN-006  
**功能名称**：月卡登记、续期与注销  
**功能描述**：对月卡车辆进行全生命周期管理。  
**前置条件**：车场已创建。  
**输入**：
- 车牌号（必填）
- 车辆类型（小型车/大型车等，选填）
- 有效期起止（必填）
- 费用（必填）
- 缴费方式：现金 / 线下转账 / 其他（运营端录入时必填，记录实收金额）
- 关联车场（必填）  
**处理流程**：
1. 用户录入月卡信息或审核小程序端申请；
2. 系统校验车牌号唯一性（同一车场内同一车牌不能重复办理）；

**输出**：月卡列表（支持到期预警筛选）。  
**异常处理**：

**业务规则**：
- 月卡状态：生效中 / 已过期 / 已注销；
- 到期后自动失效，车辆按临停计费；
- 到期前提醒天数按车场配置（车场级参数，见 ADMIN-002），本期仅在运营端到期预警列表展示，不向车主推送；
- 小程序端可申请月卡，运营端审核流程可配置（部分车场需审核，部分自动通过）；小程序端申请审核通过后须在小程序内完成模拟支付，支付成功月卡方可生效（见 MINI-005）。

**功能编号**：ADMIN-008  
**功能名称**：黑白名单配置

**输入**：

#### 3.1.10 收费规则管理

**功能编号**：ADMIN-010  
**功能名称**：计费策略配置  
**功能描述**：配置车场的临停计费规则，支持多粒度、多模式配置。  
**前置条件**：车场已创建。  
**输入**：
- 规则名称（必填）
- 适用车场（必填）
- 适用区域/通道（选填，用于差异化覆盖）
- 计费方式：按分钟累计 / 按时段阶梯 / 封顶计费（必填）
- 免费时长（分钟，选填，默认0；常见配置为15分钟）
- 时段费率（如启用时段阶梯）
- 24小时封顶金额（如启用封顶计费）
- 跨天计费规则：按自然日分段 / 连续计费（必填）
- 生效方式：立即生效 / 仅新入场生效 / 定时生效（必填）
- 定时生效时间（如选择定时生效）  
**处理流程**：
1. 用户配置计费规则；
2. 系统校验费率合法性（非负数）；
3. 保存规则，按生效方式处理。  
**输出**：收费规则列表。  
**业务规则**：
- 配置粒度：车场级为基础，支持区域/通道差异化覆盖；
- 免费时长规则：入场标记免费，超期后从免费时长结束后开始计费（如前15分钟不计入，从第16分钟起计费；15为常见配置示例，实际按规则配置值执行）；
- 跨天计费可配置：按自然日分段（每天0点重置）或连续计费（总时长计算）；
- 生效方式可选择：立即生效（已入场车辆也按新规则）、仅新入场生效（已在场车辆按旧规则）、定时生效（未来时间点生效）。

4. 支持对已支付订单发起退款：填写退款原因，订单状态更新为"已退款"。本期为模拟退款，仅记录不产生真实资金流动。  
**输出**：订单列表（含分页、搜索、筛选、排序、Excel导出）。

#### 3.2.3 实时监控

**功能编号**：BOOTH-003  
**功能名称**：出入口视频预览  
**功能描述**：实时预览出入口相机的视频画面。  
**前置条件**：相机已绑定且在线，相机已完成GB28181注册，云端流媒体网关运行正常。  
**输入**：无（自动加载）。  
**处理流程**：
1. 系统根据当前选中车场加载通道列表；
2. 每个通道加载对应相机的视频流：相机 **GB28181 主动推流** → **云端流媒体网关转封装为WebRTC** → 岗亭端浏览器播放；
3. 单相机模式显示单画面，双相机模式显示主备双画面。  
**输出**：视频预览画面。  
**业务规则**：
- **浏览器无法原生播放RTSP，必须经流媒体网关转封装**；流媒体网关部署于云端服务器（选型示例：WVP-GB28181 + ZLMediaKit、SRS等），相机位于车场内网（NAT后）、现场无边缘设备，云端无法主动拉取RTSP，故由相机通过GB28181主动注册并推流至云端流媒体网关，转封装为WebRTC供岗亭端浏览器播放（V1.2 修订）；
- **相机选型前提**：相机须支持GB28181主动推流，须在设备选型/施工前确认；若已采购相机不支持GB28181，降级方案二选一：① 车场路由器端口映射（须现场宽带为公网IP，施工前逐车场确认）；② 现场增设低成本边缘盒子运行流媒体网关（回到现场拉RTSP方案，仅该车场适用）；
- 视频延迟 ≤ 500ms（WebRTC方案，以现场上行带宽与公网链路正常为前提，单路相机建议上行带宽 ≥ 2Mbps）；
- 相机离线时显示离线提示。

### 3.4 平台-适配器-设备通信

#### 3.4.1 命令下发接口

**功能编号**：COMM-001  
**功能名称**：平台到适配器的命令下发  
**功能描述**：平台通过HTTP REST接口向适配器下发设备控制命令。  
**接口协议**：HTTP REST  
**接口端点**：
- POST /api/v1/device/register — 设备注册
- GET /api/v1/device/{id} — 设备查询
- POST /api/v1/device/{id}/open — 开闸
- POST /api/v1/device/{id}/close — 关闸
- POST /api/v1/device/{id}/sync-time — 校时
- GET /api/v1/device/{id}/status — 状态查询  
**请求参数**：设备ID、通道ID、车场ID等。  
**响应格式**：JSON，包含状态码、消息、数据。  
**业务规则**：
- 幂等性：重复下发同一命令，设备直接响应，无副作用；
- 超时重试：适配器未响应时平台自动重试（3次）；
- **部署形态（V1.2 修订）**：适配器与平台**同机云端部署**，命令下发走内网回环（127.0.0.1），适配器接口**不暴露公网**；V1.1 中"适配器须公网可达（固定IP/域名/VPN/反向隧道）、由施工方负责网络打通"的前提废止——现场无边缘设备，相机经NAT主动外连云端，无需打通现场网络；
- **相机GPIO开闸/关闸指令统一经适配器转发**，平台不直连EMQX。

---

#### 3.4.2 事件上报接口

**功能编号**：COMM-002  
**功能名称**：适配器到平台的事件上报  
**功能描述**：适配器通过HTTP Webhook向平台推送设备事件。  
**接口协议**：HTTP Webhook  
**上报事件类型**：
- 车牌识别事件（含车牌号、通道、时间、抓拍图片URL）
- 设备状态变化（在线/离线）
- 道闸状态变化（开/关）  
**请求格式**：JSON Payload。  
**响应要求**：平台返回200表示接收成功。  
**业务规则**：
- 识别事件实时推送，延迟要求 < 2秒；
- 平台需校验Webhook请求签名，防止伪造；
- **重试策略**：适配器未收到200响应时重试3次（间隔1秒/5秒/30秒）；仍失败则本地持久化进入死信队列，网络恢复后自动补发，并触发告警。

---

#### 3.4.3 适配器到设备通信

**功能编号**：COMM-003  
**功能名称**：适配器到设备的MQTT通信  
**功能描述**：适配器通过MQTT协议与相机、道闸等设备通信。  
**协议**：MQTT 3.1.1  
**Broker**：EMQX  
**Topic设计**：
- 命令下发：device/{device_id}/command
- 状态上报：device/{device_id}/status
- 识别事件：device/{device_id}/recognition  
**QoS**：命令下发 QoS 1，状态上报 QoS 0。  
**业务规则**：
- 适配器作为MQTT Client连接EMQX（同机内网连接）；
- 设备（相机）作为MQTT Client连接EMQX——**EMQX部署于云端并对公网开放，相机经现场路由器NAT主动外连**（穿透NAT，现场无需公网IP、无需端口映射），须保持长连接与断线自动重连；
- **相机经公网接入，EMQX 必须启用 MQTTS（TLS，8883端口）+ 用户名密码认证 + 设备级ACL**（每台设备仅可收发自身Topic），防止伪造设备上报假识别记录或非法下发开闸指令（见 SEC-012）；
- **平台不直接连接EMQX**，所有设备控制指令（含GPIO）统一经适配器转发；
- 适配器定期将月卡、固定车位、白名单车牌同步至相机本地白名单，用于现场降级放行（见 REL-006）；
- **相机选型前提**：相机须支持MQTT Client直连云平台（含TLS、断线重连）及本地白名单脱机放行，须在设备选型/施工前确认。

| 车牌识别相机 | GB28181 + MQTT | 视频流经GB28181主动推流至云端流媒体网关转封装（NAT穿透，V1.2 修订），控制指令MQTT（相机主动外连云端EMQX） |

### 5.3 软件接口

| 接口方 | 协议 | 用途 |
| :--- | :--- | :--- |
| 平台 → 适配器 | HTTP REST（内网回环） | 命令下发（含GPIO控制指令转发），同机部署不暴露公网 |
| 适配器 → 平台 | HTTP Webhook（内网回环） | 事件上报 |
| 平台 → 岗亭端 | WebSocket | 实时推送（远程开闸弹窗、告警、异常） |
| 岗亭端 → 流媒体网关 | WebRTC | 视频预览（网关云端部署） |
| 适配器 ↔ EMQX | MQTT（内网） | 设备通信中转 |
| 相机 → EMQX | MQTTS（公网，主动外连） | 设备接入，TLS加密 + 设备级ACL |
| 相机 → 流媒体网关 | GB28181（公网，主动推流） | 视频流推送，NAT穿透 |

### 5.4 通信接口

| 通信方向 | 协议 | 数据格式 | 安全机制 |
| :--- | :--- | :--- | :--- |
| 平台 → 适配器 | HTTP REST | JSON | 内网回环调用（同机部署，不暴露公网）+ 内部鉴权 |
| 适配器 → 平台 | HTTP Webhook | JSON | 签名验证 + 内网回环调用（同机部署，不暴露公网） |
| 平台 → 岗亭端 | WebSocket | JSON | JWT（连接鉴权）+ WSS |

## 7. 业务规则

### 7.1 计费规则

1. **免费时长**：入场时标记免费，超期后从免费时长结束后开始计费（前X分钟不计入，X按规则配置，常见配置为15分钟）。
2. **跨天计费**：可配置为按自然日分段（每天0点重置）或连续计费（总时长计算）。
3. **封顶计费**：24小时封顶金额，超出后按天重新计算或继续累计（按配置）。
4. **时段阶梯**：不同时间段可设置不同费率，支持多时段配置。
5. **收费规则生效**：可选择立即生效（已入场车辆也按新规则）、仅新入场生效（已在场车辆按旧规则）、定时生效（未来时间点生效）。

### 7.2 开闸规则

1. **自动开闸条件**：月卡/固定车位在有效期内、白名单车辆、已支付订单（含出场窗口期内）、免费放行。
2. **未支付拦截**：出场时存在未支付订单，按车场配置处理：拦截（不开闸）或允许欠费（开闸但标记欠费）。
3. **欠费追缴**：欠费中订单在小程序"待支付"标签页展示并可补缴；欠费车辆再次出场时，按车场配置处理：必须补缴欠费后放行（默认）/ 仅提醒。
4. **手动开闸**：必须输入放行原因，可选择是否计费。
5. **远程开闸**：运营端操作后，岗亭端弹窗提示。
6. **开闸幂等性**：重复下发同一开闸指令，设备直接响应，无副作用。
7. **支付出场窗口期**：出口缴费（车辆已在出口）支付成功立即开闸；提前缴费支付成功后进入出场窗口期（默认15分钟），窗口期内出口识别自动开闸，超期未出场则重新计费生成新订单。

### 7.3 订单规则

1. **订单生成**：仅临停车辆入场时生成预订单；月卡/固定车位/白名单车辆仅生成通行记录，不生成订单。出场时预订单更新为待支付并计算金额。
2. **模拟支付**：用户点击"确认支付"即模拟支付成功，订单状态更新为"已支付"。
3. **支付超时**：按车场配置的超时时间，超时后订单可手动关闭或自动关闭；超时关闭后车辆再次被出口识别时，系统重新计费并生成新的待支付订单。
4. **退款**：仅已支付订单可退款（本期为模拟退款，仅记录不产生真实资金流动）。
5. **代缴规则**：任何人可代缴任意车牌，支付记录归实际支付人，支付成功通知推送双方。

### 7.4 车辆管理规则

1. **月卡**：不绑定车位号，仅保证入场权限，到期后自动失效转临停计费。
2. **固定车位**：绑定具体车位号，该车位专属此车；系统仅记录绑定关系，不校验实际物理占用（防占用依赖现场管理）。
3. **黑白名单**：互斥，同一辆车不允许同时存在于黑白名单中。
4. **黑名单触发**：可配置为禁止入场、允许入场但告警、或按类型区分（欠费类/管理类/其他类）。
5. **无牌车**：以岗亭录入的临时车牌为准，全程按临时车牌生成订单、计费与匹配。

### 7.5 数据隔离规则

1. **超级管理员**：全平台数据可见。
2. **租户管理员**：仅可见被分配车场的数据，超级管理员可配置其可见范围。
3. **岗亭管理员**：仅可见被分配车场的数据；不隶属特定租户，可跨租户分配车场。
4. **小程序用户**：仅可见与本人绑定车辆相关的数据。

## 10. 附录

### 10.1 核心业务流程图（文字描述）

#### 临停车辆入场流程
```
车辆到达入口 → 相机识别车牌 → 适配器MQTT接收 → Webhook上报平台
→ 平台校验（黑名单/月卡/白名单/临停）
→ 临停车辆：生成预订单；月卡/固定车位/白名单：仅生成通行记录
→ HTTP REST下发开闸 → 适配器MQTT转发 → 道闸开启
→ 在场数实时更新 → 记录通行记录
```

#### 临停车辆出场流程
```
车辆到达出口 → 相机识别车牌 → Webhook上报平台 → 查找预订单
→ 计算费用 → 订单状态更新为"待支付"
→ 未支付处理：按车场配置拦截或允许欠费（标记欠费中）
→ 支付（出口缴费/提前缴费）：模拟支付成功 → 订单"已支付"
→ 车辆已在出口：立即自动开闸
→ 提前缴费：进入出场窗口期（默认15分钟），窗口期内出口识别自动开闸
→ 超时未出场：出口识别时重新计费，生成新的待支付订单
→ 出场记录更新 → 在场数实时更新
```

#### 欠费补缴流程
```
欠费车辆再次入场：正常识别入场（生成新预订单）
欠费车辆再次出场：出口识别 → 系统校验存在欠费中订单
→ 按车场配置：必须补缴（默认，合并提示补缴后放行）/ 仅提醒
→ 车主在小程序"待支付"标签页补缴 → 模拟支付成功 → 自动开闸
```

#### 无牌车通行流程
```
入场：识别失败/无牌 → 按车场策略转人工 → 岗亭手动录入临时车牌
→ 系统按临时车牌生成预订单 → 开闸放行
出场：出口识别失败 → 岗亭按入场临时车牌匹配订单
→ 计费收费 → 开闸放行（临时车牌全程视为正常车牌）
```

#### 手动开闸流程
```
岗亭管理员点击手动开闸 → 选择通道（支持批量） → 输入放行原因
→ 选择是否计费（计费输入金额/免费） → 确认开闸
→ HTTP REST下发 → 适配器MQTT转发 → 道闸开启 → 记录手动开闸日志
```

#### 运营端远程开闸流程
```
运营端选择通道 → 点击远程开闸 → 输入原因 → HTTP REST下发到适配器
→ 适配器MQTT转发到设备 → 道闸开启 → WebSocket实时通知岗亭端弹窗
→ 岗亭端显示：操作人、时间、通道、原因 → 按配置时长（默认10秒）自动消失
```

#### 月卡办理流程
```
小程序：选择车场 → 填写车辆信息 → 提交申请
运营端：按车场配置自动通过或人工审核
小程序：查看审核状态（不主动推送）
→ 审核通过 → 小程序内模拟支付 → 支付成功 → 月卡"生效中"
→ 到期自动失效转临停
（审核未通过：流程终止，不产生支付）
```

#### 模拟支付流程
```
小程序查询费用/出口识别 → 订单"待支付" → 点击"确认支付"
→ 系统模拟支付成功 → 订单"已支付" → 推送支付成功通知（代缴场景通知双方）
→ 已在出口：立即开闸；提前缴费：窗口期内出口识别开闸
→ 订单"已完成"
```
