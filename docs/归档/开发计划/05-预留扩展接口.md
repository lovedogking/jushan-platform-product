# 5. 预留扩展接口设计

> **【预留】总说明**
>
> 本章所有接口均为二期及后续扩展预留。一期仅返回 `mock` 数据或空实现，不触发真实第三方调用、不执行真实设备动作、不修改生产资金状态。所有请求/响应 DTO、枚举、错误码、URL、鉴权方式、数据库表结构已按生产标准完整设计，后续只需新增对应的 `Strategy` / `Adapter` / `Handler` 实现即可无缝切换为真实逻辑，无需改动 Controller 层接口契约与数据库表结构。
>
> 统一遵循共享规范：
> - 纯 SaaS 多租户：所有业务表必须包含 `tenant_id BIGINT NOT NULL`，所有查询强制带 `tenant_id` 过滤；
> - 软删除：所有表必须包含 `deleted_at DATETIME(3) DEFAULT NULL`，删除时更新为当前时间，查询时过滤 `deleted_at IS NULL`；
> - 主键策略：所有表使用 Snowflake 分布式ID，禁止 `AUTO_INCREMENT`；
> - 金额字段使用 `DECIMAL(18,2)` / `DECIMAL(18,4)`，代码中使用 `BigDecimal`，禁止使用 `FLOAT/DOUBLE`；
> - 车牌号码统一大写存储，业务层接收后先转大写再处理；
> - 操作日志必须记录 `operator_id`、`operator_ip`、`operation_time`、`before_value/after_value` JSON；
> - 并发控制：车位余量、优惠券库存、积分扣减使用 Redis 分布式锁 + 数据库乐观锁（`version` 字段）；
> - 时间字段使用 `DATETIME(3)` 或 `DATETIME`；
> - 预留接口统一标注【预留】，字段定义完整；
> - 代码块标注 `java` / `yaml` / `sql`。
>
> 数据库表结构定义见 `03-DDL规范.md`。
>
