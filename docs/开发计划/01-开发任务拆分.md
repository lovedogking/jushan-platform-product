## 1. 开发任务拆分

### 1.1 总体拆分策略

本任务拆分以 PRD V1.0 定稿范围为准，按 **"先跑通闭环、再叠加增值、最后生态扩展"** 原则分为三期：

- **一期 MVP（约 14~16 周）**：租户体系、车场基础设置、收费规则、车辆登记、进出策略、余位管控、云岗亭、车主小程序、订单支付、日志审计。目标是让一条标准车场能完成识别→计费→收费→放行闭环。
- **二期 增值运营（约 10~12 周）**：商家优惠、会员积分、充电优惠、访客管理、电子发票、短信与增值业务、报表中心。目标是在基础停车运营之上建立 B2B2C 商业能力。
- **三期 生态扩展（约 6~8 周）**：相机设备档案与指令预留、高级审批流、数据开放平台、智能分析。目标是补齐硬件管理和数据运营能力。

> 所有任务均须遵守全局约束：多租户 `tenant_id`、软删除 `deleted_at`、金额 `BigDecimal`、车牌大写存储、操作日志记录变更前后 JSON、并发控制使用 Redis 锁或乐观锁、岗亭端支持 PWA 离线缓存。

## 1.2 一期 MVP：基础车场运营

### Sprint 1：平台底座与租户体系（第 1~2 周）

#### TASK-0101 多租户数据隔离基座
- **任务类型**：【后端】
- **描述**：基于 MyBatis-Plus 租户插件实现 `tenant_id` 自动注入；所有新增表必须包含 `tenant_id` 字段并建立索引；查询拦截器自动追加 `tenant_id` 条件；超级管理员跨租户查询走独立接口并记录审计。
- **前置任务**：无
- **预计工时**：3 人天
- **涉及数据库表**：`tenant`（租户主表，如不存在则新增）、所有业务表公共字段规范
- **API 接口**：无新增业务接口
- **前端页面/组件**：无
- **核心算法/逻辑要点**：
  - MyBatis-Plus `TenantLineInnerInterceptor` 配置，忽略系统表（如 `tenant`、`auth_code`）。
  - 线程上下文透传 `tenant_id`，禁止从前端直接信任 `tenantId`。
  - 跨租户查询接口显式传入目标 `tenant_id` 并校验超级管理员权限。
- **测试要点**：
  - 同一 SQL 在不同租户上下文中返回不同结果。
  - 直接拼接 SQL 绕过租户拦截器失败。
  - 超级管理员跨租户查询成功，普通管理员越权失败。
- **验收标准**：
  - 任意业务表新增记录自动写入当前租户 `tenant_id`。
  - 未带 `tenant_id` 的查询被拦截或报错。
  - 单元测试覆盖以上三种场景。

#### TASK-0102 公司/集团档案管理
- **任务类型**：【后端】
- **描述**：实现公司/集团多级树形档案 CRUD，支持集团-公司-分公司三级架构，与车场档案中的所属公司/集团关联。
- **前置任务**：TASK-0101
- **预计工时**：3 人天
- **涉及数据库表**：`company`
- **API 接口**：
  - `POST /api/v1/companies` 新增公司
  - `PUT /api/v1/companies/{id}` 编辑公司
  - `DELETE /api/v1/companies/{id}` 软删除公司
  - `GET /api/v1/companies/{id}` 查询详情
  - `GET /api/v1/companies/tree` 查询公司树
- **前端页面/组件**：无
- **核心算法/逻辑要点**：
  - 软删除前校验无关联车场/账号；存在子节点时禁止删除父节点。
  - 树形结构使用路径编码或递归 CTE 查询。
- **测试要点**：
  - 跨租户公司数据隔离。
  - 删除有子节点或关联车场时失败。
  - 树形查询包含完整层级。
- **验收标准**：CRUD 接口联调通过，数据隔离测试通过。

#### TASK-0103 管理员账号与角色体系
- **任务类型**：【后端】
- **描述**：实现一级/二级/三级管理员账号 CRUD，支持密码策略、锁定策略；实现自定义角色与权限矩阵（菜单权限 + 操作权限 + 数据范围）。
- **前置任务**：TASK-0101、TASK-0102
- **预计工时**：5 人天
- **涉及数据库表**：`admin_account`、`custom_role`、`role_permission`
- **API 接口**：
  - `POST /api/v1/admin-accounts` 创建账号
  - `PUT /api/v1/admin-accounts/{id}` 编辑账号
  - `DELETE /api/v1/admin-accounts/{id}` 软删除
  - `GET /api/v1/admin-accounts/{id}` 详情
  - `GET /api/v1/admin-accounts` 分页列表
  - `POST /api/v1/admin-accounts/{id}/reset-password` 重置密码
  - `POST /api/v1/custom-roles` 创建自定义角色
  - `PUT /api/v1/custom-roles/{id}` 编辑角色
  - `GET /api/v1/custom-roles/{id}/permissions` 获取权限矩阵
  - `PUT /api/v1/custom-roles/{id}/permissions` 保存权限矩阵
- **前端页面/组件**：无
- **核心算法/逻辑要点**：
  - 三级管理员必须绑定单个车场；二级管理员可绑定多个车场或全部。
  - 密码使用 BCrypt 加密，登录失败 5 次锁定 30 分钟。
  - 权限矩阵使用位图或 JSON 存储，登录时缓存到 Redis。
- **测试要点**：
  - 二级管理员仅能看到本租户账号。
  - 三级管理员无法查看其他车场数据。
  - 无权限按钮接口拒绝。
- **验收标准**：账号角色体系可支撑后续所有模块的权限控制。

- **涉及数据库表**：`auth_code`

  - `PUT /api/v1/auth-codes/{id}/disable` 禁用授权码

- **前端页面/组件**：无

- **验收标准**：授权码生命周期完整，激活后租户可使用对应功能。

#### TASK-0105 操作日志基础服务
- **任务类型**：【后端】
- **描述**：封装统一操作日志服务，记录操作人、IP、时间、操作类型、操作对象、变更前后值（JSON）、操作结果；支持异步写入。
- **前置任务**：TASK-0101、TASK-0103
- **预计工时**：3 人天
- **涉及数据库表**：`business_log`
- **API 接口**：内部服务，无直接业务接口
- **前端页面/组件**：无
- **核心算法/逻辑要点**：

  - 敏感字段（手机号、密钥）在日志中脱敏。

- **验收标准**：后续所有配置类接口可一键接入操作日志。

## 1.6 关键依赖与风险

### 关键依赖
1. **P云开放平台接口**：支付、停车记录同步、固定车同步、无感支付等接口依赖P云开放平台，需申请 `app_id` + `app_secret` + `park_uuid` + `merchant`。
2. **P云车场进件**：需先完成车场进件获取 `park_uuid` 和商户号，才能进行支付测试。
3. **P云支付渠道配置**：进件后需通过P云商户平台申请支付渠道（微信/支付宝等）。
4. **税控系统对接**：电子发票税控对接【预留】，需商务确认服务商。
5. **地图服务**：车场地图选点需申请高德/百度地图 Key。

### 主要风险
1. **P云接口变更风险**：P云接口版本升级可能导致字段变更，需关注P云文档更新。
2. **P云联调依赖**：P云测试环境联调需要P云配合，可能存在等待时间。
3. **开闸真实动作风险**：Device Access 未就绪时，测试开闸必须使用 HTTP Mock，禁止用真机制造重复动作。
4. **并发资金安全**：储值车余额、优惠券库存、积分扣减必须严格使用 Redis 锁 + 乐观锁，需重点压测。
5. **PWA 离线冲突**：岗亭端离线操作同步时可能出现数据冲突，需设计清晰的冲突处理策略。
6. **多租户隔离**：所有查询必须带 `tenant_id`，任何新增接口都需要隔离测试。
7. **金额精度**：全系统金额计算统一使用 `BigDecimal`，前端展示保留两位小数，后端存储到分。
8. **P云数据同步完整性**：入场/离场记录必须实时推送P云，断网时需设计补偿机制。
