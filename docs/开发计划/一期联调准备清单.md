## 1. 联调目标

| 目标 | 说明 |
|------|------|
| 识别→计费→收费→放行 完整闭环 | 一条标准车场完成临时车/月卡车全流程 |
| Device Access v0.4 HTTP 接口联调 | 设备管理、开闸、关闸、显示屏、语音 |
| Webhook 车牌识别事件推送联调 | Device Access → 平台创建/匹配停车记录 |
| P云支付预下单/支付通知联调 | 被扫模式支付 + 回调通知 |

## 4. Device Access 联调项

### 4.1 设备管理接口

| 接口 | 验证内容 | 请求示例 | 预期结果 | 状态 |
|------|----------|---------|----------|------|
| `POST /api/v1/devices` | 设备注册 | `{"deviceSn":"TEST_CAM_001","vendor":"ZHENSHI","model":"C5H","type":"CAMERA"}` | 201 Created，返回 deviceId | ☐ |
| `GET /api/v1/devices` | 设备列表查询 | — | 200 OK，返回设备列表 | ☐ |
| `GET /api/v1/devices/{deviceId}` | 设备详情查询 | — | 200 OK，返回设备详情 | ☐ |
| `PUT /api/v1/devices/{deviceId}` | 设备更新 | `{"name":"入口相机01"}` | 200 OK | ☐ |
| `DELETE /api/v1/devices/{deviceId}` | 设备删除 | — | 200 OK / 204 No Content | ☐ |

### 4.2 设备控制接口

| 接口 | 验证内容 | 预期结果 | 平台调用点 | 状态 |
|------|----------|----------|-----------|------|
| `POST /api/v1/devices/{deviceId}/gate/open` | 开闸 | 闸杆抬起，返回 200 + ACKNOWLEDGED | 出场支付成功、人工开闸 | ☐ |
| `POST /api/v1/devices/{deviceId}/gate/close` | 关闸 | 闸杆落下，返回 200 + ACKNOWLEDGED | 运营后台手动关闸 | ☐ |
| `POST /api/v1/devices/{deviceId}/display/text` | 显示屏文字 | LED 屏显示指定内容 | 入场显示"欢迎光临"，出场显示收费金额 | ☐ |
| `POST /api/v1/devices/{deviceId}/display/config` | 显示屏配置 | 音量/亮度/方向更新生效 | 运营后台显示屏控制弹窗 | ☐ |
| `POST /api/v1/devices/{deviceId}/voice/control` | 语音播报 | 喇叭播放指定语音 | 出场时播报收费金额 | ☐ |
| `POST /api/v1/devices/{deviceId}/time/sync` | 校时 | 设备时间同步为服务器时间 | 设备管理页校时按钮 | ☐ |
| `GET /api/v1/devices/{deviceId}/status` | 状态查询 | 返回在线/离线状态 | 设备管理页状态显示 | ☐ |

### 4.3 事件推送接口

| 接口 | 验证内容 | 推送方式 | 预期结果 | 平台处理 | 状态 |
|------|----------|---------|----------|---------|------|
| `POST /api/v1/device-webhook/events` | 车牌识别事件 (ENTRY) | Device Access → 平台 HTTP POST | 平台创建 ParkingRecord，状态=ENTERED | 创建停车记录 + 入场session + 扣减余位 | ☐ |
| `POST /api/v1/device-webhook/events` | 车牌识别事件 (EXIT) | Device Access → 平台 HTTP POST | 平台匹配在场记录，计算费用，生成订单 | 匹配在场记录 + 计算费用 + 生成待支付订单 | ☐ |
| `POST /api/v1/device-webhook/events` | 重复 eventId | Device Access 重复推送 | 平台幂等忽略，不重复创建记录 | 返回 200，业务忽略 | ☐ |
| `POST /api/v1/device-webhook/events` | 未知 deviceSn | Device Access 推送未知设备 | 平台记录错误日志，返回 200 | 不处理，不抛异常 | ☐ |

### 判断标准

- **通过**：每个接口返回预期状态码和字段值
- **部分通过**：核心控制接口（开闸/关闸/识别事件）通过，辅助接口可后续补测
- **失败**：核心接口返回 5xx、超时或数据不一致，需排查

## 5. P云支付联调项

| 检查项 | 验证内容 | 请求/触发方式 | 预期结果 | 状态 |
|--------|----------|-------------|----------|------|
| `POST /api/v1/mini/pay/prepare` | 预下单 | 岗亭端/小程序提交支付请求 | 返回 prepayParams（含 prepayId） | ☐ |
| 被扫支付 | 岗亭扫码枪扫描付款码 | 岗亭端输入付款码 → 调 P云 API | 支付成功 | ☐ |
| `POST /api/v1/mini/pay/notify` | 支付回调通知 | P云异步回调平台 | 订单状态更新为 PAID | ☐ |
| 回调幂等 | 重复回调 | 同一 notify 重复发送 | 订单状态不重复更新 | ☐ |
| 回调验签 | 非法回调 | 伪造回调请求 | 验签失败，拒绝处理 | ☐ |
| WebSocket 推送 | 支付成功通知岗亭端 | 支付回调处理完成后推送 | 收费面板更新为"已支付，请放行" | ☐ |
| 退款 | 退款操作 | 运营后台发起退款 | 退款成功，订单状态更新 | ☐ |

### 判断标准

- **通过**：预下单返回合法参数，支付回调正常处理，验签和幂等正确
- **部分通过**：基础支付流程通过，幂等/退款可后续补测
- **失败**：支付回调无法正常处理或状态更新不一致

## 6. 端到端场景

### 6.1 临时车入场

| 步骤 | 操作 | 预期结果 |
|------|------|----------|
| 1 | Device Access 推送入口车牌识别事件（ENTRY） | 平台收到 Webhook |
| 2 | 平台 DeviceWebhookController 接收并处理事件 | 记录日志 |
| 3 | 平台创建 ParkingRecord（状态=ENTERED）+ ParkingSession | 数据库插入成功 |
| 4 | 平台调用 DeviceAccessClient.openGate() 开闸 | 返回 CommandResultDTO |
| 5 | 闸杆抬起 | 物理闸杆动作 |
| 6 | 岗亭 WebSocket 收到入场通知 | 监控大屏显示入场记录 |
| 7 | 车位余量 -1 | 数据库余量字段更新 |

**验证点**：停车记录创建、开闸成功、WebSocket 推送、余量更新

## 8. 风险与兜底

| 风险 | 影响 | 概率 | 严重程度 | 兜底方案 |
|------|------|------|---------|----------|
| 开闸失败（设备离线/厂商异常） | 车辆无法出场 | 中 | 高 | 岗亭端人工放行兜底，自动创建异常告警 |
| 支付超时（P云接口响应慢） | 订单状态不一致 | 低 | 高 | 后端主动查询支付状态 + 人工确认 |
| Webhook 重复推送 | 重复创建停车记录 | 中 | 中 | 幂等校验（eventId + deviceSn + captureTime 唯一约束） |
| 设备离线（无心跳） | 无法识别/开闸 | 中 | 高 | 岗亭端手动输入车牌 + 人工开闸兜底 |
| 网络中断（平台 ↔ Device Access） | 控制指令超时 | 低 | 高 | 指令标记为 UNCERTAIN，通过状态查询确认设备状态 |
| P云回调丢失 | 订单一直为 PENDING | 低 | 高 | 定时任务主动查询超时未支付订单 + 人工对账 |
| Webhook IP 白名单配置错误 | Device Access 推送被拒绝 | 低 | 中 | 开发环境允许 `*`，生产环境配置准确 IP |
| SN 映射不一致 | 开闸调用失败 | 中 | 中 | 联调前核对平台台账 SN 与 Device Access 设备 SN 一致 |

### 兜底操作流程

#### 开闸失败兜底

```
开闸调用失败 / 超时
    ├── 返回 UNCERTAIN 状态
    ├── 创建异常告警（设备故障）
    ├── 停车记录保持 PAID（不变成 EXITED）
    └── 岗亭操作员可选择：
        ├── 再次尝试开闸（记录重试原因）
        └── 人工确认放行（记录操作人和原因）
```

#### 支付异常兜底

```
支付回调超时
    ├── 岗亭端显示"支付处理中"
    ├── 后端定时任务查询 P云支付状态
    ├── 付款码有效期内可重试预下单
    └── 人工确认支付后操作：
        ├── 在运营后台手动确认订单
        └── 确认后手动触发开闸
```
