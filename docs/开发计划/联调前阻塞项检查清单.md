## 使用说明

- 本清单用于 **一期 MVP 前后端联调启动前** 的阻塞项检查
- 每项需明确 **负责人** 和 **验收标准**
- 任一 P0 项未通过，禁止进入与设备侧联调
- 检查通过后，由技术负责人签字确认

## 一期已完成能力（Device Access v0.4 联调就绪）

以下能力已通过 Device Access v0.4 实现，适用于一期前后端联调和设备真机联调：

### 设备控制（通过 Device Access v0.4 HTTP API）

| 能力 | 端点 | 联调状态 | 备注 |
|------|------|---------|------|
| 校时 | `POST /devices/{deviceSn}/time/sync` | ✅ 就绪 | 同步相机系统时间 |
| 状态查询 | `GET /devices/{deviceSn}/status` | ✅ 就绪 | 查询在线/离线状态 |
| 开闸 | `POST /devices/{deviceSn}/gate/open` | ✅ 就绪 | 臻识/信路通已实现，可对接真机 |
| 关闸 | `POST /devices/{deviceSn}/gate/close` | ✅ 就绪 | |
| 显示屏文字 | `POST /devices/{deviceSn}/display/text` | ✅ 就绪 | 通过相机下发 LED 显示 |
| 显示屏配置 | `POST /devices/{deviceSn}/display/config` | ✅ 就绪 | 音量/亮度/方向 |
| 语音播报 | `POST /devices/{deviceSn}/voice/control` | ✅ 就绪 | |

### 事件接收（HTTP Webhook）

| 能力 | 推送方式 | 联调状态 | 平台处理 |
|------|---------|---------|---------|
| 车牌识别事件 | Device Access → `POST /api/v1/device-webhook/events` | ✅ 就绪 | 创建停车记录、触发入场/出场流程 |
| 入场事件 | 经由车牌识别事件判断 `direction=ENTRY` | ✅ 就绪 | 创建 ParkingSession，扣减余位 |
| 出场事件 | 经由车牌识别事件判断 `direction=EXIT` | ✅ 就绪 | 匹配在场记录，计算费用，生成订单 |

### 平台侧联调前置要求

- Device Access 服务端已部署（含 v0.4 端点）并配置平台端的 Webhook 回调地址
- 平台 `DeviceAccessClient` 已配置为指向真实 Device Access 地址（而非 Mock）
- 设备已在 Device Access 侧注册，SN 已录入平台设备台账
- 车道方向配置与设备绑定的方向一致
