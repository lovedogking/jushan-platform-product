# 基础响应与认证契约

> 版本：1.0.0（R01 冻结）
> 适用范围：admin-web、booth-web、miniapp、停车业务平台后端
> 冻结日期：2026-07-11

## 1. 统一响应结构

所有 REST JSON 接口统一使用以下结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "traceId": "01J..."
}
```

### 1.1 字段定义

| 字段        | 类型       | 规则                      |
| --------- | -------- | ----------------------- |
| `code`    | number   | `0` 表示业务成功，非 `0` 表示业务失败 |
| `message` | string   | 面向调用方的结果描述，**不再使用 `msg`** |
| `data`    | 泛型或 null | 业务数据；没有返回数据时为 `null`（始终序列化） |
| `traceId` | string   | 服务端生成的请求追踪标识（始终序列化） |
| `errors`  | object 或 null | 可选。仅参数校验失败等场景出现，`null` 时不序列化 |

### 1.2 errors 字段

`errors` 为可选字段，仅用于参数校验失败场景。普通成功响应、普通业务失败不得携带 `errors`。

**数据结构**：字段名校验错误列表。

```json
{
  "code": 400,
  "message": "参数校验失败",
  "data": null,
  "traceId": "...",
  "errors": [
    { "field": "name", "message": "名称不能为空" },
    { "field": "phone", "message": "手机号格式不正确" }
  ]
}
```

**约束**：

- `errors` 仅用于 `@Valid` / `@Validated` 触发的字段级校验失败。
- 普通成功响应（`code=0`）不使用 `errors`。
- 普通业务失败（如"订单不存在"）不使用 `errors`。
- 缺少必填参数、类型不匹配等 Servlet 层参数错误不使用 `errors`（仅返回 `message`）。
- `errors` 数组中每项包含 `field`（字段名）和 `message`（校验错误描述）。

### 1.3 业务成功判断

```typescript
// ✅ 正确
response.code === 0

// ❌ 禁止（旧契约）
response.code === 200
response.code !== 200
```

### 1.4 错误信息读取

```typescript
// ✅ 正确
const msg = response.message

// ❌ 禁止（旧契约）
const msg = response.msg
```

## 2. HTTP 状态码规则

| HTTP 状态码 | 语义 | 典型场景 |
|------------|------|---------|
| 200 | 请求已正常处理（业务成功或普通业务失败） | 正常响应、普通业务异常（code=1000 等） |
| 400 | 参数或请求格式错误 | 参数校验失败、缺少必填字段、JSON 格式错误、业务 code=400 |
| 401 | 未认证或会话无效 | Token 过期、未登录、业务 code=401 |
| 403 | 已认证但无权限 | 角色无权限访问接口、业务 code=403 |
| 404 | 资源不存在 | 接口路径不存在、业务 code=404 |
| 409 | 资源或状态冲突 | 重复操作、状态不允许、业务 code=409 |
| 429 | 请求过于频繁 | 限流、业务 code=429 |
| 500 | 未处理的服务端错误 | 未知异常、系统内部错误 |

**BusinessException HTTP 状态映射规则**：

- 错误码为 `400`/`401`/`403`/`404`/`409`/`429` → 对应 HTTP 状态码
- 其他普通业务错误码（如 `1000`、`20001` 等）→ HTTP 200

不得把所有异常强制包装成 HTTP 200。

无业务数据时仍返回完整响应结构，`data=null`，不使用 HTTP 204。

## 3. TraceId 规则

1. 每个 HTTP 请求由服务端生成唯一 traceId（UUID 去连字符）。
2. 入站 `X-Trace-Id` 请求头会被校验（长度 ≤64，仅允许 `[a-zA-Z0-9_-]`），不合法时重新生成。
3. 所有正常和异常响应体均携带 `traceId`。
4. 响应头 `X-Trace-Id` 同步返回 traceId。
5. 日志中通过 `%X{traceId}` 输出。
6. 请求结束后 MDC 自动清理，不污染线程池复用。

## 4. 认证基础契约

### 4.1 Token Header

```http
Authorization: Bearer <accessToken>
```

禁止使用：

- 自定义 `token` Header
- `satoken` Header
- 裸 Token（无 Bearer 前缀）
- URL 查询参数 Token
- Cookie 和 Header 双重混用

### 4.2 Token 存储键

统一使用：

```
jushan_access_token
```

| 客户端 | 存储方式 |
|--------|---------|
| admin-web | `localStorage` |
| booth-web | `localStorage` |
| miniapp | `wx.setStorageSync` |

禁止继续使用的旧键：

- `parking_token`
- `booth_token`
- `token`

### 4.3 登录接口

```
POST /api/auth/login
Content-Type: application/json
```

请求：

```json
{
  "username": "admin",
  "password": "password"
}
```

成功响应 `data`：

```json
{
  "accessToken": "token-value",
  "tokenType": "Bearer",
  "expiresInSeconds": 7200,
  "user": {
    "userId": "1",
    "username": "admin",
    "displayName": "管理员",
    "roles": [],
    "permissions": []
  }
}
```

### 4.4 退出接口

```
POST /api/auth/logout
Authorization: Bearer <accessToken>
```

成功响应：

```json
{
  "code": 0,
  "message": "success",
  "data": null,
  "traceId": "..."
}
```

### 4.5 查询当前会话

```
GET /api/auth/session
Authorization: Bearer <accessToken>
```

成功响应 `data`：

```json
{
  "userId": "1",
  "username": "admin",
  "displayName": "管理员",
  "roles": [],
  "permissions": []
}
```

**不再使用** `/auth/info`。

## 5. 客户端行为规范

### 5.1 HTTP 401 处理

- 清理本地 Token（`localStorage.removeItem` / `wx.removeStorageSync`）
- 跳转登录页
- **防止多个并发 401 重复跳转或重复弹窗**
- 登录接口自身失败不触发跳转循环

### 5.2 HTTP 403 处理

- **不清理仍可能有效的 Token**
- 返回明确的无权限错误
- 不自动跳转登录

### 5.3 Token 安全

- 登录请求不得携带旧 Token
- 无 Token 时不发送空 `Authorization` Header
- 日志、错误信息、调试输出中禁止打印完整 Token

## 6. 禁止兼容的旧契约

以下旧模式一律禁止使用和新增：

| 旧模式 | 替换为 |
|--------|-------|
| `code === 200` | `code === 0` |
| `response.msg` / `data.msg` | `response.message` / `data.message` |
| `/auth/info` | `/auth/session` |
| `placeholder_token` | 调用 `/api/auth/login` 获取真实 Token |
| 裸 Token Header | `Authorization: Bearer <token>` |
| `parking_token` / `booth_token` | `jushan_access_token` |
