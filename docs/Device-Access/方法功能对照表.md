# Device Access 方法功能对照表（臻识 C5H）

> 以代码（`ZhenshiMessageHandler` / `ZhenshiDeviceCoordinator`）和臻识 C5H MQTT 协议为准。
> 固件版本：bv=16771

---

## 1. MQTT 通信基础

### 1.1 MqttMessage 消息结构

臻识 C5H 与平台通过 EMQX MQTT 3.1.1 通信，消息体为标准 JSON：

| 字段 | 类型 | 说明 |
| :--- | :--- | :--- |
| `id` | String | 消息唯一标识（UUID），用于请求-响应匹配 |
| `sn` | String | 设备序列号 |
| `name` | String | 消息名称，用于路由到对应处理器 |
| `version` | String | 协议版本，固定 `"1.0"` |
| `timestamp` | Long | Unix 秒级时间戳 |
| `code` | Integer | 响应码（仅设备回复时），200=成功 |
| `payload` | Object | 消息体，结构依 name 不同 |

### 1.2 Topic 模式

| 方向 | Topic 模板 | 说明 |
| :--- | :--- | :--- |
| **上行**（设备→平台） | `device/{sn}/message/up/{name}` | 设备上报消息（心跳、识别结果等） |
| **下行**（平台→设备） | `device/{sn}/message/down/{name}` | 平台下发命令 |

具体下行 topic 常量定义在 `ZhenshiMessageHandler`：

| Topic 常量 | 模板值 |
| :--- | :--- |
| `TOPIC_SET_TIME` | `device/%s/message/down/set_time` |
| `TOPIC_SERIAL_DATA` | `device/%s/message/down/serial_data` |
| `TOPIC_GATE_DIRECT_OPEN` | `device/%s/message/down/gate_direct_open` |
| （内联） | `device/%s/message/down/gpio_out` |
| （内联） | `device/%s/message/down/set_io_lock_status` |

### 1.3 `publishAndWait` 机制

所有下行命令通过 `MqttGateway.publishAndWait(topic, command, timeout, TimeUnit.SECONDS)` 发送：
- 使用 `ConcurrentHashMap<String, CompletableFuture<MqttMessage>>` 维护待响应 Future
- 设备回复匹配 `message.id` → 完成 Future
- 超时（默认 10 秒）→ `TimeoutException`

#### 3.1.4 解除道闸锁定（取消常开）— `unlockGate`

| 层级 | 方法 | 文件 |
| :--- | :--- | :--- |
| **接口** | `DeviceCoordinator.unlockGate(String deviceId, UnlockGateRequest req)` | `DeviceCoordinator.java` |
| **编排** | `ZhenshiDeviceCoordinator.unlockGate(String deviceId, UnlockGateRequest req)` | `ZhenshiDeviceCoordinator.java:236-311` |
| **协议** | `ZhenshiMessageHandler.sendUnlockGate(String deviceSn, int io, long timeoutSeconds)` | `ZhenshiMessageHandler.java:437-461` |

| 项目 | 内容 |
| :--- | :--- |
| **MQTT 命令** | `set_io_lock_status` |
| **Topic** | `device/{sn}/message/down/set_io_lock_status` |
| **payload.body** | `{"ioout": 0, "status": 0}` |
| **参数说明** | `ioout`=0 → IO0，`status`=0 → 解锁（断开继电器） |
| **超时** | 10 秒 |
| **能力要求** | `LOCK_OPEN_GATE` |

**两步流程**（`ZhenshiDeviceCoordinator.unlockGate`）：

```
步骤 1：sendUnlockGate (set_io_lock_status status=0)
         ├── 失败 → 直接返回失败
         └── 成功 → 进入步骤 2

步骤 2：sendOpenGate (gpio_out io=0 value=2 delay=1500) [best-effort]
         └── 重置设备内部道闸状态机，恢复 gpio_out 命令的正常响应
```

> **背景**：固件 bv=16771 不支持 `gate_direct_open`。取消锁定时设备内部状态机未复位，导致后续 `gpio_out` 关闸命令无响应。步骤 2 通过发送一次开闸脉冲来复位状态机，使关闸命令恢复正常。

## 4. 设备能力（Capability）与命令对照

数据库中设备的 `capabilities` 字段（JSON 数组）决定哪些命令可用：

| 能力枚举 | 对应命令 | 缺少时的行为 |
| :--- | :--- | :--- |
| `OPEN_GATE` | `openGate` | 抛 `UnsupportedOperationException` |
| `CLOSE_GATE` | `closeGate` | 抛 `UnsupportedOperationException` |
| `LOCK_OPEN_GATE` | `lockGate` / `unlockGate` | 抛 `UnsupportedOperationException` |
| `TIME_SYNC` | `syncTime` | —（Coordinator 层未做能力校验） |
| `DISPLAY_TEXT` | `displayText` | 抛 `UnsupportedOperationException` |
| `DISPLAY_SAVE` | `saveDisplay` | 抛 `UnsupportedOperationException` |
| `DISPLAY_CONFIG` | `configDisplay` | 抛 `UnsupportedOperationException` |
| `DISPLAY_ENHANCED` | `displayTextEnhanced` | 抛 `UnsupportedOperationException` |
| `VOICE_CONTROL` | `controlVoice` | 抛 `UnsupportedOperationException` |
| `PERIPHERAL_CONTROL` | `controlPeripheral` | 抛 `UnsupportedOperationException` |

当前设备实际能力：

## 7. 道闸 IO 端口约定

臻识 C5H 的 GPIO 端口与道闸继电器的对应关系：

| IO 编号 | 物理端口 | 用途 | 使用命令 |
| :--- | :--- | :--- | :--- |
| **IO0** | 开闸继电器 | 开闸脉冲、常开锁定 | `gpio_out` io=0 / `set_io_lock_status` ioout=0 |
| **IO1** | 关闸继电器 | 关闸脉冲 | `gpio_out` io=1 |

`gpio_out` 的 `value` 参数：
| value | 含义 |
| :--- | :--- |
| 0 | 低电平 |
| 1 | 高电平 |
| 2 | 先通后断脉冲（最常用） |

`set_io_lock_status` 的 `status` 参数：
| status | 含义 |
| :--- | :--- |
| 0 | 解锁（断开继电器） |
| 1 | 高电平锁定（继电器持续吸合） |
| 2 | 低电平锁定 |

## 8. 已知问题与注意事项

| 问题 | 详情 |
| :--- | :--- |
| **`gate_direct_open` 不支持** | 固件 bv=16771 不支持臻识协议 7.19，发送后 10 秒超时，已用 `gpio_out` 替代 |
| **`set_io_lock_status` 参数名** | 臻识协议要求参数名为 `"ioout"` 而非 `"io"`。使用 `"io"` 设备返回 200 但不执行 |
| **unlockGate 两步流程** | 取消常开后设备内部状态机不自动复位，需额外发送 `gpio_out` 开闸脉冲才能恢复关闸响应 |
| **显示屏 OLM-M1D** | 所有显示屏命令通过 RS485 串口透传，摄像头本身不解析 OLM-M1D 协议 |
| **VERTICAL 显示** | 当前未实现，调用会抛 `UnsupportedOperationException` |
