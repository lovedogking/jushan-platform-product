## 5. 构建命令详细定义（按工程划分）

### 5.1 后端（Maven 模块化单体）

```
项目根目录:
  mvn clean compile                     # 全量编译
  mvn clean test                        # 全量单元测试
  mvn clean package -DskipTests         # 全量打包（跳过测试）
  mvn verify                            # 全量集成测试
  mvn test -pl parking-module-xxx       # 指定模块测试
  mvn dependency:tree                   # 查看依赖树
  mvn flyway:migrate                    # 数据库迁移（或通过 Spring Boot 自动迁移）
  mvn clean install -DskipTests         # 安装到本地仓库
```

### 5.2 admin-web（Vue 3 + Arco Design + Vite）

```
admin-web/:
  npm install                           # 安装依赖
  npm run dev                           # 开发服务器
  npm run build                         # 生产构建
  npm run type-check                    # TypeScript 类型检查（如有）
  npm run lint                          # ESLint 检查（如有）
  npm run test                          # Vitest 单元测试（如有）
  npm run e2e                           # Playwright E2E（如有）
```

### 5.3 booth-web（Vue 3 + Arco Design + Vite，独立部署）

```
booth-web/:
  npm install                           # 安装依赖
  npm run dev                           # 开发服务器
  npm run build                         # 生产构建
  npm run type-check                    # TypeScript 类型检查（如有）
  npm run lint                          # ESLint 检查（如有）
```

### 5.4 miniapp（原生微信小程序）

```
miniapp/:
  微信开发者工具 → 预览 / 上传           # 手动操作
  npm install                           # 如有 npm 依赖
```

### 5.5 Docker Compose / 基础设施

```
项目根目录:
  docker compose config                 # 验证 compose 语法
  docker compose up -d --build          # 构建并启动所有服务
  docker compose ps                     # 查看服务状态
  docker compose logs -f <service>      # 查看服务日志
  docker compose down                   # 停止所有服务
```

## 6. 失败三分类规则

每轮任务执行验证时，将测试/构建失败归为以下三类：

### 6.1 本轮回归（This-Round Regression）

**定义**：本轮修改导致的测试/构建失败。

**判定标准**：
- 修改前该测试通过，修改后失败
- 本轮新增代码导致编译错误
- 本轮修改的 API 签名导致调用方编译失败

**处理**：**必须修复**，不得绕过。修复后重新运行全部相关测试。

### 6.2 既有失败（Pre-Existing Failure）

**定义**：修改前已存在的失败，与本次改动无关。

**判定标准**：
- `git stash` 本轮改动后，同样测试仍然失败
- 错误堆栈不涉及本轮修改的任何文件
- 是已知未完成模块的占位测试

**处理**：
- 记录证据（失败命令、首个错误、涉及文件）
- 在完成报告中列为"未完成内容/已知问题"
- 不得修复（超出本轮范围时）
- 如既有可能被本轮改动影响，提升为本轮回归处理

### 6.3 环境阻塞（Environment Blocking）

**定义**：因环境、外部依赖、真机、支付资料或第三方服务缺失导致的无法运行。

**判定标准**：
- Testcontainers 无法连接 Docker
- 需要 Device Access 真机但 Base URL / SN 未提供
- 需要微信支付商户号/证书但空值
- 需要特定端口但被占用
- 需要数据库但无法连接

**处理**：
- 记录证据
- 在完成报告中列出：未运行测试、原因、风险、后续验证命令或人工步骤
- 禁止使用"理论上可以"代替验证
- 可用 Mock/Testcontainers/WireMock 替代真机依赖

## 10. P0 禁止项清单（操作层面）

以下情况出现时，任务不得验收。每轮验证时检查：

| 编号 | 禁止项 | 检查方法 |
|:--:|------|------|
| P0-1 | 越权/跨租户/跨停车场未 fail-closed | 集成测试：跨租户请求必须返回 403/空 |
| P0-2 | 平台直连厂商设备或解析厂商协议 | 代码审查：无厂商 SDK/MQTT Topic 引用 |
| P0-3 | 修改 Device Access 源码或绕过已确认接口 | git diff 检查 |
| P0-4 | 将目标设计/未冻结契约当作当前真实能力 | 代码审查：未实现的接口标注待确认 |
| P0-5 | 信任前端 tenantId/parkingLotId/deviceSn | 代码审查：后端从可信上下文获取 |
| P0-6 | 开闸自动重试或超时直接判为未动作 | WireMock 测试：证明无自动重试 |
| P0-7 | 开闸无权限/数据范围/审计 | 代码审查 + 测试 |
| P0-8 | 支付回调未验签/未校验/浮点金额 | Mock 测试 + 代码审查 |
| P0-9 | 泄露密钥/证书/Token/签名/密码 | 日志检查 + grep |
| P0-10 | 未经授权 commit/push/破坏性 Git | git status 检查 |
