## 2. 服务间认证

> NEEDS_HUMAN_DECISION（最终方案待双方确认）。**推荐 HMAC-SHA256**。不得使用普通用户 Bearer Token 代替服务认证。

推荐方案：HMAC-SHA256（联调环境可临时降级为内网 API Key，但生产须 HMAC）。

| 项 | 推荐值 |
|----|--------|
| ClientId | `X-Client-Id`（如 `parking-platform`） |
| Timestamp | `X-Timestamp`（秒） |
| Nonce | `X-Nonce`（UUID） |
| Signature | `X-Signature`（hex） |
| 签名原文 | `ClientId\nTimestamp\nNonce\nHTTPMethod\nPath\nBodySha256` |
| 算法 | HMAC-SHA256(secret, 签名原文) |
| 时间偏差 | ±300s |
| 防重放 | Nonce TTL 600s，Redis/内存去重 |
| 密钥轮换 | 双密钥（old/new）并行期 ≥ 1 周 |
| 日志脱敏 | 不输出 Secret/签名值；SN 脱敏 `鲁Q***45` 类比 |
| 联调降级 | 仅联调环境允许 API Key（`X-Api-Key`），生产禁用 |

备选：mTLS / mTLS+HMAC（更高安全但运维复杂，首期 10~100 停车场非必须）。状态 NEEDS_HUMAN_DECISION。

## 3. 标识模型

> 目标：拆分 deviceId 与厂商 SN，不得让同一 deviceId 同时表示平台主键和厂商 SN。

| 标识 | 所有者 | 含义 | 示例 |
|------|--------|------|------|
| `tenantId` | Platform | 租户 | `tenant_001` |
| `parkingLotId` | Platform | 停车场 | `park_001` |
| `laneId` | Platform | 车道 | `lane_entry_001` |
| `platformDeviceId` | Platform | 平台逻辑设备主键 | `dev_camera_001` |
| `deviceCode` | Platform | 人类可读设备编码 | `CAMERA-001` |
| `deviceSn` | Platform 映射 / DA 通信用 | 厂商 SN（调用 DA 时使用） | `a422cb58-6c62f055` |
| `vendor` | 双方 | 厂商 | `ZHENSHI` |
| `model` | 双方 | 型号 | `C5H` |
| `deviceType` | 双方 | 设备类型 | `CAMERA` / `GATE` |
| `logicalGateDeviceId` | Platform | 逻辑道闸设备 | `dev_gate_001` |
| `executorDeviceId` | Platform | 实际执行相机 | `dev_camera_001` |
| `configVersion` | Platform | 配置版本（单调递增 int64） | `18` |

- 当前（AS-IS）：Device Access `deviceId` == 厂商 SN（`Device.deviceId` 注释"通常为设备序列号或 MAC"，注册时小写化）；
- 目标：Platform 保留 `platformDeviceId`，调用 DA 时传 `deviceSn`；DA 内部以 `deviceSn` 定位设备；
- 相机与道闸建模为两个逻辑设备：`CAMERA`（PLATE_RECOGNITION/CAPTURE/GATE_OPEN）+ `GATE`（GATE_OPEN/GATE_CLOSE），`executorDeviceId` 指向执行相机。

> NEEDS_HUMAN_DECISION：相机和道闸在平台中是否始终建成两个逻辑设备（推荐：是）。

## 4. 命令模型

> NEEDS_HUMAN_DECISION（统一入口 vs 独立路径）。**推荐统一 POST /api/v1/commands**。当前 v0.2 的校时/状态路径保留为 CURRENT-COMPATIBILITY，目标只有统一入口一个主方案。

### 4.1 命令类型

`OPEN_GATE` / `CLOSE_GATE` / `SNAPSHOT` / `REBOOT` / `SYNC_TIME`

> NEEDS_DEVICE_VERIFICATION：OPEN_GATE 的 C5H 实际机制；CLOSE_GATE 厂商是否支持；SNAPSHOT/REBOOT 真机回执。

### 4.2 命令请求

`POST /api/v1/commands` → `202 Accepted`（受理，不代表设备动作成功）

```json
{
  "commandId": "cmd_01JZ8S2V3K7FX2W8",
  "commandType": "OPEN_GATE",
  "targetDeviceId": "dev_gate_001",
  "executorDeviceId": "dev_camera_001",
  "parkingLotId": "park_001",
  "laneId": "lane_exit_001",
  "deviceSn": "a422cb58-6c62f055",
  "issuedAt": "2026-07-11T15:30:20.000+08:00",
  "expiresAt": "2026-07-11T15:30:30.000+08:00",
  "operatorType": "SYSTEM",
  "operatorId": "auto-exit",
  "reason": "PAID_EXIT",
  "payload": {},
  "traceId": "trace_01JZ..."
}
```

### 4.3 命令状态

| 状态 | 是否最终 | 说明 |
|------|----------|------|
| `RECEIVED` | 否 | 已接收，内部状态 |
| `ACCEPTED` | 否 | 已持久化并受理 |
| `EXECUTING` | 否 | 已下发/等待回执 |
| `SUCCEEDED` | 是 | 有明确成功证据 |
| `FAILED` | 是 | 有明确失败结果 |
| `TIMEOUT` | 是 | 超时未获明确结果 |
| `REJECTED` | 是 | 参数/权限/能力/状态不允许 |
| `UNCERTAIN` | 是 | 网络超时等不确定（平台不得盲目重试） |
| `EXPIRED` | 是 | 命令已过期 |

- 最终状态不可逆；晚到回执冲突时记录异常不覆盖；需重新执行须新生成 `commandId`。

### 4.4 命令查询

`GET /api/v1/commands/{commandId}` → 返回命令当前状态、生命周期时间、vendorCode、error 等。

> NEEDS_HUMAN_DECISION：统一入口 vs 独立 REST 路径（推荐统一入口）。

## 5. 事件信封与通道

> NEEDS_HUMAN_DECISION（主通道 RabbitMQ vs HTTP 回调）。**推荐 RabbitMQ 主通道 + HTTP 回调降级**。

### 5.1 主通道（推荐）：RabbitMQ

- Exchange：`device.events.v1`（topic，durable）
- 投递：至少一次；可能重复/延迟/乱序；平台用 `eventId` 幂等
- 消息属性：`contentType=application/json`、`messageId=eventId`、`type=eventType`、`correlationId=commandId/traceId`、`deliveryMode=2`

| 事件 | Routing Key |
|------|-------------|
| PLATE_RECOGNIZED | `device.plate.recognized` |
| DEVICE_ONLINE | `device.status.online` |
| DEVICE_OFFLINE | `device.status.offline` |
| DEVICE_HEARTBEAT | `device.status.heartbeat` |
| GATE_STATUS_CHANGED | `device.gate.status-changed` |
| DEVICE_ALARM | `device.alarm` |
| COMMAND_RESULT | `device.command.result` |
| IMAGE_UPLOADED | `device.image.uploaded` |
| DEVICE_CONFIG_APPLIED | `device.config.applied` |

> 若最终选 HTTP 回调为主通道，则不伪造 AsyncAPI 为主契约，改为 OpenAPI 回调契约，并在决策日志说明（见 `asyncapi/` 与冲突 C08）。当前草案以 RabbitMQ 为主生成 AsyncAPI。

### 5.2 统一事件信封

```json
{
  "eventId": "evt_01JZ...",
  "eventType": "PLATE_RECOGNIZED",
  "protocolVersion": "1.0",
  "schemaVersion": "1.0.0",
  "tenantId": "tenant_001",
  "parkingLotId": "park_001",
  "laneId": "lane_entry_001",
  "platformDeviceId": "dev_camera_001",
  "deviceCode": "CAMERA-001",
  "deviceSn": "a422cb58-6c62f055",
  "deviceType": "CAMERA",
  "vendor": "ZHENSHI",
  "vendorEventId": "vendor-msg-001",
  "occurredAt": "2026-07-11T15:30:20.123+08:00",
  "receivedAt": "2026-07-11T15:30:20.220+08:00",
  "publishedAt": "2026-07-11T15:30:20.300+08:00",
  "sequenceNo": 10001,
  "offline": false,
  "traceId": "trace_01JZ...",
  "payload": {},
  "extensions": {}
}
```

字段评估（避免过度设计）：

- **必填**：eventId、eventType、protocolVersion、schemaVersion、tenantId、parkingLotId、platformDeviceId、deviceSn、vendor、occurredAt、receivedAt、traceId、payload
- **条件必填**：laneId（设备已绑车道时）、deviceCode（平台已分配时）、sequenceNo（支持离线补传时）
- **可选**：vendorEventId、publishedAt、offline、extensions
- `extensions` ≤ 16KB，不得放图片 Base64/密钥；平台核心逻辑不依赖。

## 6. 车牌识别事件（PLATE_RECOGNIZED）

```json
{
  "payload": {
    "recognitionStatus": "SUCCESS",
    "plateNo": "鲁Q12345",
    "normalizedPlateNo": "鲁Q12345",
    "plateColor": "BLUE",
    "vehicleType": "SMALL",
    "energyType": "FUEL",
    "direction": "ENTRY",
    "confidence": 98.5,
    "triggerType": "AUTO",
    "image": {
      "objectKey": "parking/tenant_001/park_001/2026/07/11/evt_01JZ.jpg",
      "contentType": "image/jpeg",
      "sizeBytes": 328192,
      "sha256": "4b227777..."
    },
    "vendorRecordId": "vendor-msg-001"
  }
}
```

- `recognitionStatus`：SUCCESS / NO_PLATE / FAILED / LOW_CONFIDENCE / UNKNOWN
- `plateColor`：BLUE/GREEN/YELLOW/WHITE/BLACK/GRADIENT_GREEN/YELLOW_GREEN/OTHER/UNKNOWN
- `vehicleType`：SMALL/MEDIUM/LARGE/MOTORCYCLE/OTHER/UNKNOWN
- `direction`：ENTRY/EXIT/UNKNOWN
- `triggerType`：AUTO/MANUAL/RETRY/OFFLINE_UPLOAD

规则：

- 无牌车 `recognitionStatus=NO_PLATE`，`plateNo=null`，不得构造虚假车牌；
- 低置信度 `LOW_CONFIDENCE`，阈值由平台配置；
- 失败识别 `FAILED`，仍发布事件供平台记录；
- 重复识别：DA 短时间去重为基础过滤，平台以 `eventId`+设备+时间+车牌+车道+未完成记录做业务幂等；
- 离线补传：`offline=true`、`triggerType=OFFLINE_UPLOAD`、`occurredAt` 保留真实时间；
- 车牌标准化：去首尾空格、英文大写、保留中文省份、不纠错、原值 `plateNo`/标准化 `normalizedPlateNo`；
- 图片缺失：`image=null`，识别事件仍发布，后续发 `IMAGE_UPLOADED`。

> 单一 COMMAND_RESULT 取代需求规格 §7.5 的"按命令分结果事件"（开闸结果/关闸结果/抓拍结果/重启结果），用 `commandType` 区分，避免事件类型爆炸（见冲突 C12）。

## 7. 状态与告警事件

### 7.1 DEVICE_ONLINE / DEVICE_OFFLINE

- 只在状态变化时发布；
- OFFLINE `reason`：HEARTBEAT_TIMEOUT/MQTT_DISCONNECTED/TCP_DISCONNECTED/HTTP_UNREACHABLE/DEVICE_WILL_MESSAGE/MANUAL_DISABLED/AUTH_FAILED/UNKNOWN
- 恢复发布 ONLINE，平台自动关闭对应离线告警；
- 离线阈值 NEEDS_HUMAN_DECISION（推荐 60~180s；当前代码 30s，目标可配置）。

### 7.2 DEVICE_HEARTBEAT

- DA 可接收每次厂商心跳（厂商最低 5s）；
- 对平台发布可限流（推荐 30~60s 一次）；
- 在线/离线状态变化不得因限流延迟。

### 7.3 GATE_STATUS_CHANGED

- `gateStatus`：OPEN/CLOSED/OPENING/CLOSING/KEEP_OPEN/FAULT/UNKNOWN
- 厂商无法提供实际闸杆状态时，不得据"命令成功"伪造 OPEN，用 UNKNOWN；
- 命令结果与闸杆状态是两个不同概念；
- NEEDS_DEVICE_VERIFICATION：C5H 道闸状态（gpio_in/serial_data）是否真实可用。

### 7.4 DEVICE_ALARM

- `severity`：INFO/WARNING/ERROR/CRITICAL
- 第一阶段告警码：DEVICE_OFFLINE/HEARTBEAT_TIMEOUT/MQTT_DISCONNECTED/DEVICE_AUTH_FAILED/COMMAND_FAILED/COMMAND_TIMEOUT/IMAGE_UPLOAD_FAILED/CONFIG_APPLY_FAILED/TIME_DRIFT/UNKNOWN_DEVICE/VENDOR_PROTOCOL_ERROR
- 告警恢复：`recovered=true`，平台自动关闭并保留历史。

## 8. 命令结果事件（COMMAND_RESULT）

```json
{
  "payload": {
    "commandId": "cmd_01JZ...",
    "commandType": "OPEN_GATE",
    "targetDeviceId": "dev_gate_001",
    "executorDeviceId": "dev_camera_001",
    "status": "SUCCEEDED",
    "acceptedAt": "2026-07-11T15:30:20.220+08:00",
    "startedAt": "2026-07-11T15:30:20.300+08:00",
    "completedAt": "2026-07-11T15:30:21.100+08:00",
    "retryCount": 0,
    "vendorCode": "200",
    "vendorMessage": "success",
    "resultData": { "relayChannel": 1 },
    "errorCode": null,
    "errorMessage": null,
    "traceId": "trace_01JZ..."
  }
}
```

- 第一阶段至少发送最终状态：SUCCEEDED/FAILED/TIMEOUT/REJECTED；
- 相同命令只允许一个最终状态；最终状态发布失败走 Outbox 重试；平台幂等；
- HTTP 202 不能替代该事件；厂商回执不明确不得返回 SUCCEEDED；
- 平台收到 SUCCEEDED 后仍按业务规则生成出场记录。

## 9. 图片规范

- 不通过 RabbitMQ 传 Base64；
- 不在数据库存图片二进制；
- Platform 管理对象存储，签发临时上传凭证；
- DA 用临时凭证上传，计算 sha256；
- 事件中只传 `objectKey` + 元数据（contentType/sizeBytes/sha256）；
- 图片失败不阻塞识别事件（`image=null`），后续发 `IMAGE_UPLOADED`；
- 第一阶段：仅 JPEG，最大 10MB；保存期限由停车场配置，不超过平台最大期限；
- NEEDS_DEVICE_VERIFICATION：C5H 图片获取方式（云存路径下载？Base64 内容解码？）；
- NEEDS_HUMAN_DECISION：对象存储产品与桶策略。

## 10. 配置同步

> NEEDS_HUMAN_DECISION（推送 vs 拉取）。**推荐方案 C：Platform 推送刷新通知 + DA 拉取**。不得多方案并存。

配置至少包括：platformDeviceId、deviceSn、vendor、model、parkingLotId、laneId、direction、enabled、capabilities、executor mapping、heartbeatThreshold、imagePolicy、configVersion。

- `configVersion` 单调递增 int64；平台每次影响设备接入的变更递增；
- DA 持久化最后成功版本，启动加载，收到通知后拉取，不降版本，损坏回退；
- 旧版本收到返回 `IGNORED_OLDER_VERSION`；
- 禁用设备后 DA 停止业务事件、拒绝命令、保留诊断、发布 DEVICE_CONFIG_APPLIED。

## 11. 幂等

### 11.1 事件幂等（Platform Inbox）

- `unique(event_id)`；
- 消费流程：事务→插 eventId→已存在则 ACK 不重复处理→不存在则处理→提交→ACK。

### 11.2 命令幂等（Device Access 命令表）

- `unique(command_id)`；
- 首次保存完整请求摘要；重复 commandId 且摘要一致返回历史结果；不一致返回 `409001 COMMAND_ID_CONFLICT`；
- 重启后仍有效；命令记录保留 ≥ 90 天。

## 12. 重试与风险分级

| 风险 | 命令 | 当前无幂等时 | 目标有幂等后 |
|------|------|--------------|--------------|
| 高 | OPEN_GATE/CLOSE_GATE/REBOOT | 网络超时→UNCERTAIN，**禁止自动重试**，人工确认 | 确认未送达才传输层重试；设备已收但回执丢失不重复触发；平台需重开生成新 commandId |
| 中 | SNAPSHOT/SYNC_TIME | 有限次数重试 | 按规则重试 |
| 只读 | 状态查询 | 可重试 | 可重试 |

- HTTP 已受理（202）≠ 设备动作成功；
- 命令结果与实际闸杆状态是两个概念；
- 当前无 commandId：开闸网络超时进入 UNCERTAIN，**不得自动重试开闸**（见冲突 C07）。

## 13. 错误码（服务间独立契约）

> 服务间契约独立于平台前端 `code=0` 与 DA 当前 `code=200`。采用 HTTP 状态 + 6 位业务 errorCode。

| code | HTTP | 标识 | 说明 |
|------|------|------|------|
| 0/200 | 200/202 | SUCCESS/ACCEPTED | 成功/已受理（202 用于命令受理） |
| 400001 | 400 | INVALID_PARAMETER | 参数错误 |
| 400002 | 400 | MISSING_REQUIRED_FIELD | 缺少必填字段 |
| 400005 | 400 | COMMAND_EXPIRED | 命令已过期 |
| 401001 | 401 | AUTH_HEADER_MISSING | 缺少认证头 |
| 401002 | 401 | CLIENT_NOT_FOUND | ClientId 不存在 |
| 401003 | 401 | SIGNATURE_INVALID | 签名错误 |
| 401004 | 401 | TIMESTAMP_EXPIRED | 时间戳超范围 |
| 401005 | 401 | NONCE_REPLAYED | Nonce 重放 |
| 403001 | 403 | DEVICE_ACCESS_FORBIDDEN | 无权访问设备 |
| 403002 | 403 | TENANT_SCOPE_MISMATCH | 租户范围不一致 |
| 403003 | 403 | PARKING_LOT_SCOPE_MISMATCH | 停车场范围不一致 |
| 404001 | 404 | DEVICE_NOT_FOUND | 设备不存在 |
| 404002 | 404 | COMMAND_NOT_FOUND | 命令不存在 |
| 409001 | 409 | COMMAND_ID_CONFLICT | commandId 冲突 |
| 409002 | 409 | CONFIG_VERSION_CONFLICT | 配置版本冲突 |
| 409003 | 409 | DEVICE_SN_ALREADY_BOUND | SN 已绑定 |
| 422001 | 422 | DEVICE_DISABLED | 设备已禁用 |
| 422002 | 422 | CAPABILITY_UNSUPPORTED | 不支持该能力 |
| 422003 | 422 | DEVICE_OFFLINE | 设备离线 |
| 422006 | 422 | EXECUTOR_MAPPING_INVALID | 执行器映射无效 |
| 429001 | 429 | RATE_LIMITED | 请求过多 |
| 503001 | 503 | MQTT_UNAVAILABLE | MQTT 不可用 |
| 503002 | 503 | RABBITMQ_UNAVAILABLE | RabbitMQ 不可用 |
| 504001 | 504 | DEVICE_TIMEOUT | 设备超时 |
| 500001 | 500 | INTERNAL_ERROR | 内部错误 |

错误响应：

> NEEDS_HUMAN_DECISION：成功码是否统一为 0。推荐：服务间成功用 HTTP 200/202 + `code=0`（业务成功），失败用对应 HTTP + 6 位 errorCode。这样既不沿用 DA 当前 `code=200`，也不照搬前端全部 `code=0` 语义。

```json
{
  "code": 422002,
  "message": "device does not support command CAPTURE",
  "data": { "deviceSn": "a422cb58-6c62f055", "commandType": "CAPTURE" },
  "requestId": "req_01JZ...",
  "traceId": "trace_01JZ...",
```
