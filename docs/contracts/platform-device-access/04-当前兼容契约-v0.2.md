### 当前 MQTT 基础设施

`MqttGateway.publishAndWait()` 是通用请求-响应基础设施，可用于实现任何 MQTT 命令。但当前没有任何代码使用它发送开闸命令。开闸能力需要在 Adapter 层从零实现。

> Platform 当前**不可**依赖开闸接口。开闸能力需在目标版本通过统一命令 `OPEN_GATE` 重新建立，且 C5H 实际开闸机制需真机确认（见冲突 C11）。

## 5. 当前响应结构

文件：`device-access-common/.../dto/Result.java`

```json
{
  "code": 200,
  "message": "success",
  "data": {},
  "timestamp": "2026-07-11 14:30:00"
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `code` | int | 成功 `200`；失败为对应错误码 |
| `message` | string | 结果说明 |
| `data` | 泛型/null | `@JsonInclude(NON_NULL)`，失败时省略 |
| `timestamp` | LocalDateTime | 构造时设置，格式 `yyyy-MM-dd HH:mm:ss`，时区 Asia/Shanghai |

- 成功码 = **200**（非 0）。
- **无 traceId**；**无 requestId**；**无 errors 字段**。
- 这与平台前端契约（`code=0`、含 `traceId`）不同——服务间应建立独立契约（见冲突 C03、`05-目标契约-v1.0-草案 §2`）。

## 8. 当前 commandId / 幂等

> **无。** 源码无 `commandId`/`idempot`/`command_id`/`CommandStatus` 匹配。

- 仅 `MqttMessage.id`（UUID）用于内部请求-响应关联（`MqttGatewayImpl.pendingFutures`，内存 `ConcurrentHashMap`）；
- 无命令表、无命令日志、无命令状态机、无幂等保护；
- 每次校时调用都会向设备执行一次；
- 服务重启后内存关联丢失。

## 9. 当前服务认证

> **无。** 无 Spring Security 依赖，无 HMAC/mTLS/API-key 过滤器/拦截器。

- 7 个端点全部匿名开放；
- 适合受控内网联调，**不应直接暴露公网**；
- 部署最低要求：端口仅内网可达、限制调用源、禁止浏览器直连、所有调用由 Platform 后端发起。

## 16. 当前安全边界

- HTTP（非 HTTPS）；
- 无服务认证、无 IP 白名单、无 Nonce、无防重放；
- Platform 严禁浏览器/小程序直连 Device Access；
- 调用须由 Platform 后端发起，使用可信配置中的 `device_sn`，不得前端透传；
- 开闸已移除，当前无高风险命令端点；校时为运维操作。
