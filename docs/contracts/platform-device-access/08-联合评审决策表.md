### 4.1 各决策详细说明

#### B01：事件主通道

**推荐方案**：
- RabbitMQ 是正常设备事件主通道（device.events.v1 topic exchange，至少一次投递，Platform Inbox 幂等）
- HTTP 只用于补偿、人工重放和灾难恢复
- HTTP 不作为日常车牌识别主链路

**第一阶段只实现必要事件**：PLATE_RECOGNIZED、COMMAND_RESULT、DEVICE_ONLINE/OFFLINE，不一次性实现所有事件。

**Platform 意见（2026-07-11）**：

同意推荐方案。设备与 Device Access 之间继续使用 MQTT；Device Access 向 Platform 投递统一设备事件采用 RabbitMQ；Platform 不直接订阅厂商 MQTT Topic；HTTP 仅用于补偿、人工重放和灾难恢复，不作为日常识别主链路。

**Device Access 意见**：同意推荐方案。

#### B02：服务间认证

**推荐方案**：
- 开发和联调：可信内网 + HMAC-SHA256
- 生产目标：HTTPS + HMAC-SHA256
- mTLS 暂缓（阶段4 生产级引入）

**Platform 意见（2026-07-11）**：

同意推荐方案。开发和联调环境采用可信内网加 HMAC-SHA256；生产目标采用 HTTPS 加 HMAC-SHA256；mTLS 暂缓。签名应包含 ClientId、Timestamp、Nonce、请求方法、路径和请求体摘要，并具备防重放和密钥轮换能力。

**Device Access 意见**：同意推荐方案。

#### B03：设备业务主数据所有权

**推荐方案**：
- Platform 是设备业务配置唯一主数据源（管理绑定、方向、能力、启用、心跳阈值、图片策略、configVersion）
- Device Access Registry 管理通信运行数据（连接、协议配置、厂商凭证、心跳接收、原始状态、厂商回执、命令执行状态）和配置缓存
- 双方不得独立维护互相冲突的停车场、车道和业务绑定

**Platform 意见（2026-07-11）**：

同意推荐方案。Platform 是租户、停车场、车道、平台逻辑设备、设备绑定、方向、启用状态、能力和执行器映射的唯一业务主数据源。Device Access Registry 负责设备通信信息、运行状态和 Platform 配置缓存，不得独立维护与 Platform 冲突的停车场、车道和业务绑定。

**Device Access 意见**：同意推荐方案。

#### B04：设备标识拆分

**推荐定义**：
- `platformDeviceId`：Platform 内部稳定主键
- `deviceCode`：运营人员可读编码
- `deviceSn`：厂商物理设备序列号
- `logicalGateDeviceId`：平台逻辑道闸
- `executorDeviceId`：实际执行命令的相机或控制器
- `tenantId`、`parkingLotId`、`laneId`、`vendor`、`model`

**Platform 意见（2026-07-11）**：

同意推荐方案。拆分 platformDeviceId、deviceCode、deviceSn、logicalGateDeviceId 和 executorDeviceId，并明确 tenantId、parkingLotId、laneId、vendor、model 的语义。不得继续使用同一个 deviceId 同时表示 Platform 数据库主键和厂商 SN。

**Device Access 意见**：同意推荐方案。

#### B05：目标命令接口

**推荐方案**：`POST /api/v1/commands` + `GET /api/v1/commands/{commandId}`
旧接口如后续保留，只作为 CURRENT-COMPATIBILITY 适配层，不维护两套命令执行逻辑。

**Platform 意见（2026-07-11）**：

同意推荐方案。目标命令接口采用 POST /api/v1/commands 和 GET /api/v1/commands/{commandId}。旧能力独立接口如后续保留，只作为 CURRENT-COMPATIBILITY 适配层，内部统一转换为 Command，不维护两套命令执行、幂等、审计和状态逻辑。

**Device Access 意见**：同意推荐方案。

#### B06：相机和道闸建模

**推荐方案**：
- CAMERA 和 GATE 建模为两个平台逻辑设备
- CAMERA 负责识别、抓拍、连接和心跳
- GATE 表示停车业务中的逻辑闸杆执行器
- 使用 `logicalGateDeviceId` 和 `executorDeviceId` 建立执行关系

**必须强调**：命令发送成功 ≠ 厂商回复成功 ≠ 闸杆实际处于 OPEN，是三个不同事实。

**Platform 意见（2026-07-11）**：

同意推荐方案。Platform 中 CAMERA 和 GATE 建模为两个逻辑设备；CAMERA 负责识别、抓拍、连接、心跳和厂商协议，GATE 表示停车业务中的逻辑闸杆执行器；使用 logicalGateDeviceId 和 executorDeviceId 表达相机继电器实际执行开闸。

必须区分：
1. 命令已发送；
2. 厂商设备回复成功；
3. 闸杆实际处于 OPEN。

三者不得混为同一状态。

**Device Access 意见**：同意推荐方案。

#### B07：服务间响应契约

**推荐成功响应**：
```json
{ "code": 0, "message": "success", "traceId": "xxx", "data": {} }
```

**推荐错误响应**：
```json
{ "code": 404001, "errorCode": "DEVICE_NOT_FOUND", "message": "device not found", "traceId": "xxx", "data": null }
```

HTTP 状态码仍真实表达：400、401、403、404、409、429、500、503。

**Platform 意见（2026-07-11）**：

同意推荐方案。目标服务间成功响应采用 code=0、message、traceId 和 data；错误响应增加稳定 errorCode 字段（如 DEVICE_NOT_FOUND）。HTTP 状态码继续真实表达 400、401、403、404、409、429、500 和 503。HTTP 202 只表示命令已受理，不等于设备执行成功，也不等于闸杆实际打开。

**Device Access 意见**：同意推荐方案。

#### B08：第一阶段最小设备能力范围

**必须实现**：PLATE_RECOGNIZED、OPEN_GATE、COMMAND_RESULT、STATUS、eventId、commandId、traceId、Device Access Outbox、Platform Inbox、人工兜底、UNCERTAIN 状态。

**可以保留**：SYNC_TIME。

**下一阶段**：SNAPSHOT。

**暂缓**：CLOSE_GATE、REBOOT、KEEP_OPEN、CANCEL_KEEP_OPEN。

**Platform 意见（2026-07-11）**：

同意推荐方案。

第一阶段必须包含：PLATE_RECOGNIZED、OPEN_GATE、COMMAND_RESULT、STATUS、eventId、commandId、traceId、Device Access Outbox、Platform Inbox、至少一次投递、重复事件幂等、UNCERTAIN、人工开闸兜底、操作审计。

可以保留：SYNC_TIME。

下一阶段：SNAPSHOT。

暂缓：CLOSE_GATE、REBOOT、KEEP_OPEN、CANCEL_KEEP_OPEN、信路通、完整图片补传、完整离线运行。

**Device Access 意见**：同意推荐方案。

## 8. 第一阶段最小闭环范围

```
真实 C5H 识别报文
  → Device Access 转换为 PLATE_RECOGNIZED
  → Device Access Outbox
  → RabbitMQ
  → Platform Inbox 幂等消费
  → Platform 创建入场或出场记录
  → Platform 完成放行决策
  → POST /api/v1/commands 提交 OPEN_GATE
  → Device Access 使用 commandId 幂等
  → Device Access 向真实设备下发开闸
  → Device Access 发布 COMMAND_RESULT
  → Platform 更新设备命令记录
```

### 必须包含

- eventId、commandId、traceId
- Device Access Outbox、Platform Inbox
- 至少一次投递、重复事件处理
- UNCERTAIN 状态、不自动重试结果不确定的开闸
- 人工开闸兜底、操作审计

### 不被以下能力阻塞

- 完整图片、IMAGE_UPLOADED
- 关闸、重启、常开
- 信路通第二品牌
- 完整配置同步
- 完整离线缓存
- 正式收费日期

> Platform 当前没有任何可以组合成真实停车主链路的 Device Access 接口集合。校时、状态查询和设备 CRUD 只能作为开发或联调能力使用。
