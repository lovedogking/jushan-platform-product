## 1. 状态定义

每项功能标注以下状态之一：

| 状态 | 含义 |
|------|------|
| `IMPLEMENTED` | 代码已实现且经测试或真机验证 |
| `PARTIALLY_IMPLEMENTED` | 部分实现（如解析已做、上报未做） |
| `DOCUMENTED_ONLY` | 仅文档描述，代码未实现 |
| `PLANNED_NEXT` | 下一阶段必须实现 |
| `DEFERRED` | 暂缓，远期考虑 |
| `OUT_OF_SCOPE` | 本期不做 |
| `NEEDS_DEVICE_VERIFICATION` | 需真机确认后才能定状态 |

## 4. 当前/下一阶段/远期汇总

### 4.1 当前已实现（CURRENT-IMPLEMENTED）

**Device Access：** MQTT 连接/重连、设备 CRUD、识别结果接收与解析、心跳、校时（含回执与超时）、在线判定（按需）、统一响应（code=200）。

**Platform：** 租户/停车场/多租户隔离（部分）、设备逻辑档案与绑定（文档级别）。

### 4.2 下一阶段必须实现（PLANNED_NEXT，阶段1 最小真机闭环）

**Device Access：** 车牌识别事件上报（PLATE_RECOGNIZED）、开闸（需真机确认机制）、commandId 幂等、命令查询、统一命令入口、事件可靠投递（RabbitMQ）、服务间认证、定时离线检测、事件统一模型发布。

**Platform：** 设备逻辑档案与绑定、放行决策、入场/出场/停车记录、命令审计、RabbitMQ 消费、Inbox 幂等、服务间签名客户端、设备状态展示。

### 4.3 远期（DEFERRED / 阶段2-4）

关闸、重启、抓拍（需真机）、图片上传、配置同步、离线补传、告警、月卡/白名单/黑名单、支付、信路通第二品牌、多停车场多实例、mTLS/Outbox/DLQ、监控告警、24~72h 连续运行。
