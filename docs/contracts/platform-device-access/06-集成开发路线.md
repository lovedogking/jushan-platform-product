## 3. 阶段1：最小真机闭环

**目标**：真实识别事件 → Platform 创建入场 → 出口识别 → Platform 判断放行 → Device Access 开闸 → 命令结果 → Platform 完成出场。

### 最小必要能力（仅阶段1 真正阻塞项）

- PLATE_RECOGNIZED 事件上报（RabbitMQ 主通道）
- OPEN_GATE 命令（统一入口 + commandId 幂等）
- COMMAND_RESULT 事件
- STATUS 查询（兼容 v0.2 路径或统一路径）
- 基础服务认证（HMAC-SHA256，联调可降级）
- eventId / commandId / traceId
- Platform Inbox 幂等 + Device Access Outbox
- 人工兜底（岗亭确认 + 现场开闸 + 审计）

> **非阻塞**：完整图片上传、关闸、重启、信路通第二品牌、完整离线缓存容量、正式收费试运营日期。这些不在阶段1 阻塞范围内。

### Platform 任务
1. 设备逻辑档案与绑定（platformDeviceId/deviceCode/deviceSn 分离、车道/方向/能力）；
2. 调用前校验（权限/租户/停车场/车道/启用/SN 可信）；
3. DeviceAccessClient（统一命令入口 + 兼容校时/状态）；
4. 命令审计表（含 traceId、result_status=SUCCESS/FAILED/UNCERTAIN）；
5. RabbitMQ 消费 + Inbox 幂等（unique event_id）；
6. PLATE_RECOGNIZED → 入场/出场记录；
7. 放行决策 → 下发 OPEN_GATE；
8. COMMAND_RESULT → 生成出场记录完成订单；
9. 超时 UNCERTAIN 处理 + 人工兜底；
10. HMAC 签名客户端。

### Device Access 任务
1. RabbitMQ 发布（Exchange device.events.v1）；
2. PLATE_RECOGNIZED 事件发布（基于已实现的 PlateRecognizedEvent）；
3. 统一命令入口 POST /api/v1/commands + commandId 幂等 + 命令表；
4. OPEN_GATE 实现（NEEDS_DEVICE_VERIFICATION C5H 开闸机制）；
5. COMMAND_RESULT 事件发布；
6. 命令查询 GET /api/v1/commands/{commandId}；
7. 定时离线检测 + DEVICE_ONLINE/OFFLINE；
8. HMAC 验签；
9. eventId/traceId 贯穿；
10. Outbox（事件与业务同事务）。

### 契约交付物
- openapi/asyncapi/schemas 冻结；
- 联调环境（RabbitMQ vhost、ClientId、测试 SN、测试 tenant/park/lane）。

### 联调测试（见 §7 用例）
- 正常识别入场/出场、重复识别、相同 eventId 重复投递、无牌车、低置信度、图片缺失、心跳、离线、恢复、道闸状态、开闸、开闸拒绝、超时、不确定、相同 commandId 重复、过期命令、不支持命令、未绑定停车场、错误车道、非法签名、重放、通道短暂不可用、本地缓存补传、乱序、过期状态、多停车场隔离。

### 进入条件
- 阶段0 冻结；
- 真机到位，C5H 开闸机制确认。

### 退出条件
- 真机完成"识别→入场→放行→出场"闭环；
- 命令幂等与事件幂等验证通过；
- 无 P0 冲突遗留。

### 阻塞项
- C5H 开闸机制未确认（冲突 C11）；
- 事件通道未定（冲突 C08）。

### 是否需要真实设备
- 是。
