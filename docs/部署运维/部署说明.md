## 1. 本地开发环境

项目使用 Docker Compose 编排本地依赖服务：MySQL 8.4、Redis 7、RabbitMQ 4.x、Nginx。

### 1.1 快速开始

```bash
# 1. 复制并编辑环境变量
cp .env.example .env

# 2. 启动所有服务
docker compose up -d

# 3. 查看服务状态
docker compose ps

# 4. 查看日志
docker compose logs -f

# 5. 停止并清理
docker compose down

# 6. 停止并清理数据卷（重置数据库）
docker compose down -v
```

### 1.2 服务端口

| 服务 | 宿主机端口 | 容器端口 | 说明 |
|---|---|---|---|
| MySQL | 3307 | 3306 | 避免与宿主机 MySQL 冲突 |
| Redis | 6378 | 6379 | 避免与宿主机 Redis 冲突 |
| RabbitMQ AMQP | 5672 | 5672 | |
| RabbitMQ Management | 15672 | 15672 | |
| Nginx | 8088 | 80 | 避免与宿主机 80 冲突 |

### 1.3 数据卷

| 卷名 | 用途 |
|---|---|
| `jushan-mysql-data` | MySQL 持久化数据 |
| `jushan-redis-data` | Redis AOF 持久化数据 |
| `jushan-rabbitmq-data` | RabbitMQ 持久化数据 |

### 1.4 健康检查

所有服务均配置了 Docker healthcheck，Nginx 会等待 MySQL、Redis、RabbitMQ 全部健康后才启动。

## 2. 后端与前端运行

Docker Compose 仅启动基础设施，后端 Spring Boot 和前端 Vite dev server 在宿主机运行：

```bash
# 后端（端口 8080）
mvn clean compile
mvn spring-boot:run -pl parking-boot

# admin-web（端口以 Vite 配置为准）
cd admin-web
pnpm install
pnpm dev

# booth-web
cd booth-web
pnpm install
pnpm dev
```

---

## 3. Nginx 反向代理

Nginx 配置文件位于 `docker/nginx/`。

- 生产环境挂载前端构建产物：
  - `admin-web/dist` → `/usr/share/nginx/html/admin`
  - `booth-web/dist` → `/usr/share/nginx/html/booth`
- 开发阶段前端使用 Vite dev server，Nginx 仅作反向代理。
- 后端 API 通常通过 `/api` 前缀代理到 `host.docker.internal:8080`。

---

## 4. 生产部署差异

| 项 | 本地开发 | 生产目标 |
|---|---|---|
| 数据源 | 本地 MySQL | 生产 MySQL 集群 |
| Redis | 单实例 | Redis 集群或哨兵 |
| RabbitMQ | 单节点 | 集群 |
| Nginx | HTTP | HTTPS |
| 敏感配置 | 写入 `application-local.yml` | 通过环境变量注入 |
| 日志 | 控制台输出 | 收集到日志平台 |

---

## 5. 初始化数据

首次启动 MySQL 时会自动执行 `docker/mysql/init/` 目录下的 SQL 脚本（可选）。

业务表结构由 Flyway 迁移脚本自动创建，无需手动执行 DDL。
