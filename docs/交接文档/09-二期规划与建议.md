## 三、关键依赖与风险

| 依赖 | 影响 | 建议 |
|---|---|---|
| **微信商户号申请** | 阻塞 P0-4 上线 | **尽早启动**，外部流程周期长（1-2 月） |
| **计费体系二选一** | P0-1 必须前置决策 | 建议：废弃旧 BillingRule，解冻 FeeRule |
| **P云对接去留** | 微信支付上线后需制定切换策略 | 可并行运行一段时间后下线 P云 |
| **xxl-job 引入** | P1-3 提醒 + P0-6 对账都需要 | 基础设施决策，建议尽快引入 |
| **断网本地开闸** | 需硬件/离线方案评估 | 评估相机本地白名单能力 + 岗亭本地服务 |
| **信路通设备** | 仅当引入时才需完成 | 按需开发 |

## 四、建议的开发顺序

```
第 1 步：基础设施
  ├── 计费体系决策（废弃 BillingRule，解冻 FeeRule）
  ├── 引入 xxl-job
  └── 微信商户号申请（尽早启动）

第 2 步：P0 核心交付
  ├── P0-1 计费引擎定型 + 前端配置页
  ├── P0-4 微信支付服务商模式
  ├── P0-2 临时车全流程联调
  ├── P0-5 改价功能
  └── P0-6 对账

第 3 步：P0 兜底
  ├── P0-3 跟车处理
  └── P0-3 断网本地开闸

第 4 步：P1 月卡商业化
  ├── P1-3 到期管理（xxl-job）
  ├── P1-1 产品化
  └── P1-2 小程序续费

第 5 步：P2/P3
  ├── P2 小程序前端
  ├── P3 经营数据
  └── DA 协议完善（白名单/重启/触发识别/信路通）
```

## 五、给接手者的建议

1. **先跑通部署**：按照 [部署运维手册](./02-部署运维手册.md) 走一遍完整部署流程
2. **熟悉岗亭核心链路**：识别→判定→开闸→日志→WebSocket 是全平台最关键的流
3. **计费决策优先**：新旧计费并存是最紧急的技术债，尽早解决
4. **尽量不改多租户拦截器**：`JushanTenantLineHandler` 已稳定，改动影响面大
5. **查阅代码索引**：`docs/code-index/` 下是全部类的路径索引，不要盲目 grep
6. **文档同步**：AGENTS.md 要求任何代码变更必须同步更新需求文档和代码索引
