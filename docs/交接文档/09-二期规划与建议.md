## 三、关键依赖与风险

| 依赖 | 影响 | 建议 |
|---|---|---|
| **P云 商户号/接口权限申请** | 阻塞 P0-4 上线 | **尽早启动**，外部流程周期长 |
| **计费 runtime 双轨** | P0-1 主体已完成 | 识别链路与 H5 已迁移至 `FeeCalculationService` / `FeeRule`，4 个 DB 列 + 版本快照 + 入场快照已补齐；剩余 `BillingEngine` 引用清理与旧 `BillingRule` 删除见 A6 |
| **P云 OpenAPI 策略** | H5 真实支付与停车场侧被 P云 调用 | 生产环境走 P云 OpenAPI；`PyunPpFrontController`（PP 体系）复活用于停车场侧被 P云 调用；模拟支付保留为 fallback |
| **定时任务框架** | P1-3 提醒 + P0-6 对账都需要 | 已决策：采用 Spring Scheduler，不引入 xxl-job |
| **断网本地开闸** | 需硬件/离线方案评估 | 评估相机本地白名单能力 + 岗亭本地服务 |
| **信路通设备** | 仅当引入时才需完成 | 按需开发 |

## 四、建议的开发顺序

```
第 1 步：基础设施与决策
  ├── 计费体系：FeeRule 补列 + 计算补全 + 版本快照 + 入场快照
  ├── 定时任务：Spring Scheduler（不用 xxl-job）
  └── P云 商户号/接口权限申请（尽早启动）

第 2 步：P0 核心交付
  ├── P0-1 识别链路切到 FeeRule + 删除旧 BillingRule
  ├── P0-4 P云 OpenAPI 真实支付（H5 + 回调幂等 + 商户配置）
  ├── P0-2 临时车全流程联调
  ├── P0-5 改价功能
  └── P0-6 对账（Spring Scheduler）

第 3 步：P0 兜底
  ├── P0-3 跟车处理
  └── P0-3 断网本地开闸（纳入 P0）

第 4 步：P1 月卡商业化
  ├── P1-3 到期管理（Spring Scheduler）
  ├── P1-1 产品化
  └── P1-2 小程序续费

第 5 步：P2/P3
  ├── P2 小程序前端
  ├── P3 经营数据
  └── DA 协议完善（白名单/重启/触发识别/信路通）
```

## 五、给接手者的建议

1. **先跑通部署**：按照 [部署运维手册](./02-部署运维手册.md) 走一遍完整部署流程
2. **熟悉岗亭核心链路**：识别→判定→开闸→日志→WebSocket 是全平台最关键的流
3. **计费收尾优先**：识别链路与 H5 已切换 FeeRule，剩余 `BillingEngine` 引用（ParkingFeeService/MiniPayController/PyunPpFrontController/BillingRuleController）清理与旧 BillingRule 删除（A6）是当前最紧急的技术债，尽早完成
4. **尽量不改多租户拦截器**：`JushanTenantLineHandler` 已稳定，改动影响面大
5. **查阅代码索引**：`docs/code-index/` 下是全部类的路径索引，不要盲目 grep
6. **文档同步**：AGENTS.md 要求任何代码变更必须同步更新需求文档和代码索引
7. **修复 `plate_number` 默认值问题**：当前 `recognition_event_log` 表的 `plate_number` 字段无默认值，非识别事件会导致 SQL 错误。执行 `ALTER TABLE recognition_event_log MODIFY plate_number VARCHAR(32) DEFAULT '';`
8. **修复 DA 数据库编码问题**：`t_device_product` 表存在 UTF-8 双重编码乱码。将 JDBC URL 中的 `characterEncoding=utf-8` 改为 `characterEncoding=UTF-8`
9. **为 DA 添加健康检查端点**：当前 `curl http://127.0.0.1:8082/actuator/health` 返回 404，建议在 DA 的 `application-prod.yml` 中启用 actuator health endpoint
10. **确认 EMQX 密码是否正确**：`.env.production` 中 Redis 和 EMQX 密码相同，建议确认是否为预期配置
