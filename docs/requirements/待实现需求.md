## P0 计费与支付

| # | 需求 | 状态 | 现状 / Gap |
|---|---|---|---|
| P0-1 | 计费规则引擎：按车型/时段计费，免费时长、首小时、阶梯、每日封顶、跨天规则；按停车场维度可配置；运营端配置页面 | ◧ | `FeeCalculationService` 已支持 4 种计费模式 + 免费时长 + 首时段 + 跨天封顶（见 `modules-parking.md`），但**整体冻结**、无运营端配置页（仅岗亭 FeeRuleEditModal）、按车型定价的规则模型待规格化。**Gap**：解冻定版 + 配置页面 + 车型维度 + ≥10 个计费测试用例验收 |
| P0-2 | 临时车全流程：识别入场→计费→出场缴费→开闸 | ◧ | 主链路已通（RecognitionEventService → FeeCalculationService → 开闸）。**Gap**：全流程联调验收 + 异常分支 |
| P0-3 | 异常场景：无牌车、识别纠错、跟车、断网兜底 | ◧ | 无牌车（temp-plate）、识别纠错已有；**跟车处理未见实现（待核实）**；断网仅前端离线请求重放，**本地开闸 + 恢复后补传记录未实现** |
| P0-4 | 微信支付接入：Native 扫码 + 小程序支付，**服务商模式**；保留模拟支付开关；支付渠道可插拔、预留支付宝 | ◻️ | 现为 P云对接 + 模拟支付，代码中无任何微信支付服务商模式实现、无渠道抽象层 |
| P0-5 | 岗亭收费：金额确认、改价（需权限+操作日志）、现金收费登记、远程开闸；岗亭操作全部留日志 | ◧ | 收费确认/现金（交班汇总）/远程开闸/费用减免已有；**改价（独立权限+日志）未见实现（待核实）**；操作日志已有 audit_log 基础，需按规格补齐覆盖 |
| P0-6 | 对账：每日支付流水与订单自动对账，对不上产生告警 | ◻️ | 无任何对账实现（monitor_alert 表可作告警载体） |

## 遗留风险与依赖

| 项 | 说明 | 影响 |
|---|---|---|
| 微信商户号申请 | 服务商模式资质清单与申请周期长（外部依赖） | 阻塞 P0-4 上线时间，需尽早启动 |
| 计费体系二选一 | 旧 `BillingRule`（线上在用）vs 新 `FeeRule`（冻结）并存 | P0-1 启动前必须决策迁移/切换策略 |
| P云对接去留 | 现支付走 P云；微信支付服务商模式上线后需制定切换/共存策略 | P0-4 方案设计前置 |
| 断网本地开闸 | 需要硬件/离线方案评估（相机本地白名单？岗亭本地服务？） | P0-3 方案设计前置 |
| xxl-job 引入 | 项目当前无任何定时任务框架（P1-3 提醒、P0-6 对账都需要） | 基础设施决策 |
