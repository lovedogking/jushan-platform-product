# 二期实施计划

> **最近更新**：2026-08-11  
> **依据**：`docs/adr/0001-fee-rule-migration.md`、`待实现需求.md`  
> **目标**：完成计费引擎迁移、H5 支付闭环、月卡商业化、小程序端、经营数据补齐。

---

## 一、计划概览

| 工作线 | 优先级 | 核心目标 |
|---|---|---|
| A. FeeRule 计费引擎完整化 | P0 | 补齐 DB/计算/版本/快照，替换 BillingEngine |
| B. H5 支付闭环 | P0 | 切 FeeRule 计费，接 P云 OpenAPI 真实支付 |
| C. 岗亭与异常场景 | P0 | 改价权限、断网本地开闸 |
| D. 月卡商业化 | P1 | 到期提醒/转临停/宽限期、季卡年卡产品化 |
| E. 小程序端 | P2 | 启动 `miniapp/` 前端工程 |
| F. 经营数据与对账 | P1/P2 | 对账、报表规格化 |
| G. 文档与索引 | 贯穿 | ADR、需求文档、代码索引同步更新 |

---

## 二、A 线：FeeRule 计费引擎完整化

### A1. 补齐 fee_rule 数据模型

| 项 | 内容 |
|---|---|
| 任务 | `fee_rule` 表新增 4 列：`first_period_minutes`、`max_amount`、`cross_day_mode`、`effect_mode` |
| 关联代码 | `FeeRule` Entity、`FeeRuleCreateCmd`/`FeeRuleUpdateCmd`、`FeeRuleVO`、`FeeRuleMapper`、`FeeRules.vue`、`FeeRuleEditModal.vue` |
| 验收 | Flyway 迁移通过；运营端可配置新字段；旧数据默认值合理 |

### A2. FeeRule 版本管理

| 项 | 内容 |
|---|---|
| 任务 | 新建 `fee_rule_history` 附表；每次 `update` 时将旧规则整行 + 时段 JSON 快照写入历史；支持版本列表与回退 |
| 关联代码 | `FeeRuleService.update`、新增 `FeeRuleHistoryService`/`Mapper`/`Entity`、运营端新增「历史版本」入口 |
| 验收 | 改规则后可在运营端查看历史版本；回退后计算结果与历史版本一致 |

### A3. FeeRule 计算能力补全

| 项 | 内容 |
|---|---|
| 任务 | `FeeCalculationService` 实现：`first_period_minutes` 首时段、`max_amount` 整单封顶、`nightCap`、`cross_day_mode`（自然日/连续24h）、`priority` 优先级匹配、`vehicleType`/`plateColor`/`zoneId` 过滤 |
| 关联代码 | `FeeCalculationService`、`FeeRuleMapper.selectActiveByLotId`、计费测试用例 |
| 验收 | `/api/v1/fee/calculate` 试算结果与旧 BillingEngine 等价或覆盖全部场景；≥10 个测试用例通过 |

### A4. 规则快照与生效方式

| 项 | 内容 |
|---|---|
| 任务 | 入场时把生效 `fee_rule` 快照 JSON 写入 `parking_session.fee_rule_snapshot`；`effect_mode` 支持 `IMMEDIATE`/`SCHEDULED`/`NEW_ENTRY_ONLY` |
| 关联代码 | `ParkingSessionService.entry`、`ParkingSession` Entity、出场计费读取快照 |
| 验收 | 改规则不影响已入场车辆；"仅新入场生效"模式下旧记录按旧规则计费 |

### A5. 识别链路切换

| 项 | 内容 |
|---|---|
| 任务 | `EntryService`、`ExitService`、`RecognitionEventServiceImpl`、`TempPlateService` 等旧 `BillingEngine` 调用全部改为 `FeeCalculationService.calculateFeeCents` |
| 关联代码 | `modules/booth/service/*`、`modules/parking/service/ParkingSessionServiceImpl` |
| 验收 | 识别→出场全流程费用计算走 FeeRule；`parking_lot.fee_rule_id` runtime 生效 |

### A6. 删除旧 BillingRule

| 项 | 内容 |
|---|---|
| 任务 | 删除 `billing_rule*` 表、Entity、Mapper、Service、Controller、前端页面；清理 `PyunPpFrontController` 中 `BillingEngine` 引用 |
| 关联代码 | `com.jushan.system.*` 计费相关、`modules/parking/service/BillingEngine.java`、旧运营端 BillingRule 页面 |
| 验收 | 全仓库无 `BillingEngine`/`BillingRule` 引用；编译通过；回归测试通过 |

## 三、B 线：H5 支付闭环

### B1. H5 后端切 FeeRule

| 项 | 内容 |
|---|---|
| 任务 | `H5FeeController` / `H5PayController` 中 `BillingEngine.calculateFee` 替换为 `FeeCalculationService.calculateFeeCents` |
| 关联代码 | `modules/h5/controller/*` |
| 验收 | H5 查费/支付金额与岗亭/运营端一致 |

### B2. P云 OpenAPI 真实支付接入

| 项 | 内容 |
|---|---|
| 任务 | `H5PayController.prepare` 调 P云 OpenAPI 下单，返回 `pay_url`；新增 P云 回调接口处理支付通知（幂等）；`confirm.vue` 真实支付分支跳转 `pay_url` |
| 关联代码 | `modules/h5/controller/H5PayController.java`、`h5-user/src/views/pay/confirm.vue`、新增 `PyunOpenApiClient` |
| 验收 | 生产环境关闭 mock 后可完成真实支付；回调幂等，重复通知不重复入账 |

### B3. P云 PP 接口复活（停车场侧对接 P云）

| 项 | 内容 |
|---|---|
| 任务 | 去掉 `PyunPpFrontController` 的 `@Deprecated`；将其计费入口切到 `FeeCalculationService`；修复 `/api/v1/pyun/*` 回调幂等 |
| 关联代码 | `modules/parking/controller/PyunPpFrontController.java`、`modules/parking/controller/PyunNotifyController.java` |
| 验收 | P云 可调通停车场侧接口；计费结果正确 |

### B4. P云 商户配置管理

| 项 | 内容 |
|---|---|
| 任务 | `PayMerchantConfig` 已有表，补运营端 CRUD 页面 |
| 关联代码 | `modules/parking/entity/PayMerchantConfig.java`、新增 `PayMerchantConfigController`、运营端新增页面 |
| 验收 | 运营端可配置 P云 `app_id`、`app_secret`、`park_uuid` 等参数 |

## 十、风险与依赖

| 风险 | 影响 | 应对 |
|---|---|---|
| FeeRule 与 BillingEngine 计费结果不一致 | 收费错误 | 建立 ≥10 个测试用例，逐项对比；上线前灰度 |
| P云 商户号/接口权限申请周期长 | 阻塞 B2/B3 | 尽早申请并并行开发 |
| 断网本地开闸硬件方案不确定 | 阻塞 C2 | 第 3 周前确定岗亭本地服务/浏览器 Storage 方案 |
| 旧 BillingRule 删除后无快速回滚 | 上线风险 | 上线前全量 DB 备份；保留 feature flag |
