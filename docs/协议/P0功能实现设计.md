## 总体架构

```
┌──────────────┐  ┌───────────────┐  ┌────────────────────┐
│  parking-    │  │  device-access │  │  设备 (臻识/芊熠)     │
│  system      │──│  (DA 中间层)   │──│  MQTT / HTTP        │
│  (业务)      │  │                │  │                     │
└──────┬───────┘  └───────┬───────┘  └─────────────────────┘
       │                   │
  ┌────┴────┐        ┌────┴────┐
  │ Device  │        │ Adapter │  品牌适配层：
  │ Service │        │ 臻识/芊熠│  协议差异在此处理
  └─────────┘        └─────────┘
```

**原则**：
- `DeviceAccessClient` 接口定义通用能力（`openGate` / `syncWhitelist` / `syncTime` 等）
- DA Adapter 层负责协议翻译——臻识 HTTP comet 回复 vs MQTT 发布 vs 芊熠 MQTT 发布
- 业务层（parking-system）不感知具体协议

## 1. 白名单下发到设备 ⭐ P0（3天）

### 1.1 目的

平台月卡车/VIP车变更时，实时同步到设备本地白名单。设备断网时依靠本地白名单自主放行。重连后全量补齐。

### 1.2 数据流

```
车辆增/删/改
    │
    ▼
SysVehicleService
    │
    ├── 在线 → DeviceService.syncWhitelistItem(deviceIds, plate, action)
    │              │
    │              ▼
    │         DeviceAccessClient.syncWhitelistItem(deviceSn, cmd)
    │              │
    │              ▼
    │         DA Adapter
    │           ├── 臻识 HTTP: comet reply { white_list_operate }
    │           ├── 臻识 MQTT: publish device/{sn}/message/down/white_list_operator
    │           └── 芊熠 MQTT: publish {cmd}/whitelist_add
    │
    └── 离线 → 记录到 whitelist_sync_log (pending)
                      │
               设备重连 → 触发全量同步
```

### 1.3 新增模块

```
parking-system/
├── modules/device/
│   ├── service/
│   │   └── DeviceWhitelistSyncService.java    ← 新建：白名单同步服务
│   └── entity/
│       └── DeviceWhitelistSyncLog.java        ← 新建：同步日志
│
device-access/
├── device-access-api/
│   └── dto/
│       └── WhitelistSyncCmd.java              ← 新建：下发命令 DTO
│
parking-boot/src/main/resources/db/migration/
└── V20260906015__device_whitelist_sync.sql    ← 新建：同步日志表
```

### 1.4 数据库

```sql
CREATE TABLE device_whitelist_sync_log (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    device_id BIGINT NOT NULL,
    plate_number VARCHAR(32) NOT NULL,
    action VARCHAR(16) NOT NULL COMMENT 'ADD/DELETE/CLEAR',
    enable_time DATETIME COMMENT '生效时间',
    overdue_time DATETIME COMMENT '失效时间',
    need_alarm TINYINT DEFAULT 0 COMMENT '0白名单/1黑名单',
    sync_status VARCHAR(16) NOT NULL DEFAULT 'PENDING' COMMENT 'PENDING/SYNCED/FAILED',
    error_message VARCHAR(512),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    synced_at DATETIME,
    INDEX idx_device_status (device_id, sync_status)
);
```

### 1.5 接口设计

**DeviceAccessClient 新增：**
```java
// 单条白名单操作
WhitelistSyncResultDTO syncWhitelistItem(String deviceSn, WhitelistSyncCmd cmd);
// 全量清空
WhitelistSyncResultDTO clearWhitelist(String deviceSn);
// 全量下发（断网恢复时）
WhitelistSyncResultDTO syncWhitelistFull(String deviceSn, List<WhitelistSyncCmd> items);
```

**WhitelistSyncCmd：**
```json
{
  "action": "ADD" | "DELETE" | "CLEAR",
  "plate": "京A12345",
  "enableTime": "2026-01-01 00:00:00",   // 可选，不填=永久
  "overdueTime": "2026-12-31 23:59:59",   // 可选
  "needAlarm": 0                           // 0=白名单，1=黑名单
}
```

### 1.6 触发时机

| 时机 | 操作 |
|------|------|
| 新增/更新车辆（月卡/VIP/固定车） | 查该车场全部在线设备 → 逐台下发 ADD |
| 删除/禁用车辆 | 逐台下发 DELETE |
| 设备首次注册上线 | 查询该车场全部有效白名单 → 全量下发 |
| 设备断网重连（MQTT connect） | 全量下发 |
| 定时任务（凌晨3点） | 检查 sync_log 中 PENDING 项，补发 |

### 1.7 与现有 SysVehicleService 集成

在 `SysVehicleServiceImpl.addVehicle()` / `updateVehicle()` / `removeVehicle()` 的末尾增加回调 hook，异步触发白名单同步（不阻塞主流程，同步失败不影响车辆本身的增删改）。

## 2. 道闸状态监控 P0（1天）

### 2.1 目的

设备订阅道闸开到位/关到位 IO 输入事件，岗亭端实时展示道闸状态，防止重复开闸/异常告警。

### 2.2 协议

| 品牌 | 协议 | Topic / 接口 |
|------|------|-------------|
| 臻识 HTTP | comet 回复无状态推送；改为轮询模式 | 开闸后查询 gpio 状态 |
| 臻识 MQTT | 订阅 `device/{sn}/message/up/gpio_in` | 开到位/关到位 IO 上报 |
| 芊熠 MQTT | 上行 `io_event` | `{ type: "io_event", status: ... }` |

### 2.3 实现方式

**方案**：利用已有 MQTT 通道，设备上报 IO 状态 → DA Adapter → `DeviceStateService` 更新状态表 → WebSocket 推岗亭端。

```
Device (MQTT gpio_in) → MqttMessageListener
    │
    ▼
DeviceStateService.onGateStatusChanged(deviceSn, status)
    │
    ├── 更新 device_gate_status 表
    └── BoothWebSocketPublisher.pushGateStatus(laneId, status)
```

### 2.4 新增模块

```
parking-system/
├── modules/device/
│   └── service/DeviceStateService.java       ← 新建：设备状态（道闸/在线）
│
parking-boot/src/main/resources/db/migration/
└── V20260906016__device_gate_status.sql
```

### 2.5 数据库

```sql
CREATE TABLE device_gate_status (
    device_id BIGINT NOT NULL PRIMARY KEY,
    gate_status VARCHAR(16) COMMENT 'OPEN/CLOSED/OPENING/CLOSING/UNKNOWN',
    status_updated_at DATETIME,
    last_open_at DATETIME,
    last_close_at DATETIME
);
```

### 2.6 前端

岗亭车道卡片旁显示道闸状态小图标：🟢开 / 🔴关 / 🟡未知

## 3. 常开/关闸命令 P0（0.5天）

### 3.1 目的

补充现有「开闸（脉冲）」之外的两种能力——常开锁定（消防/维护模式）和关闸（解除常开）。

### 3.2 协议

| 能力 | 臻识 HTTP | 臻识 MQTT | 芊熠 MQTT |
|------|-----------|-----------|-----------|
| 常开锁定 | `SetIoLockStatus { ioout:0, status:1 }` | `set_io_lock_status { io:0, value:1 }` | `open_gate_keep_open { keep_open:1 }` |
| 关闸 | `SetIoLockStatus { ioout:0, status:0 }` | `set_io_lock_status { io:0, value:0 }` | `open_gate_keep_open { keep_open:0 }` |

### 3.3 接口

**DeviceAccessClient 新增：**
```java
CommandResultDTO lockOpenGate(String deviceSn, String commandId);  // 常开
CommandResultDTO unlockGate(String deviceSn, String commandId);    // 关闸（解除常开）
```

### 3.4 实现

`DeviceService` 新增 `lockOpen()` / `unlock()` 方法，复用现有 `openGate()` 的审计日志模式。

### 3.5 前端

岗亭车道卡片旁增加一个「常开」开关按钮（消防/维护模式使用，需二次确认）。

## 4. 显示屏基础参数 P0（1天）

### 4.1 目的

可远程配置设备的显示屏文字颜色、翻转方向、亮度和音量，不用跑现场。

### 4.2 协议

| 参数 | 臻识 HTTP/MQTT | 芊熠 MQTT |
|------|---------------|-----------|
| 文字颜色 | `font.color` (0白/1红/2蓝/3绿) | `lcd_set_screen.color` |
| 翻转方向 | `rotate_mode` (0正常/1翻转) | `lcd_set_param.rotation` |
| 亮度 | `led_bright_time_ctrl[].level` (0-5) | `lcd_set_param.brightness` |
| 音量 | `media_voice_time_ctrl[].voice_level` (0-5) | 无 |

### 4.3 新增字段

在 `device` 表已有 `display_welcome_template` / `display_deny_template` 之上新增：

```sql
ALTER TABLE device
    ADD COLUMN display_text_color INT DEFAULT 0 COMMENT '0白/1红/2蓝/3绿',
    ADD COLUMN display_rotate_mode INT DEFAULT 0 COMMENT '0正常/1翻转',
    ADD COLUMN display_brightness INT DEFAULT 3 COMMENT '0熄屏-5最亮',
    ADD COLUMN display_volume INT DEFAULT 3 COMMENT '0静音-5最大';
```

### 4.4 实现

`DeviceService.updateDisplayConfig(deviceId, config)` → DA Adapter 下发。

触发时机：
- 设备管理页「显示屏」区段保存时
- 设备注册上线时（读取配置下发）

### 4.5 前端

设备管理编辑弹窗新增「显示屏」区段：颜色下拉、翻转开关、亮度滑块、音量滑块。

## 5. 设备时间同步 P0（0.5天）

### 5.1 目的

定期同步设备时间，确保识别记录时间戳准确。

### 5.2 协议

| 品牌 | 方式 | 消息 |
|------|------|------|
| 臻识 HTTP | comet 回复 | `{ TimeSync: { timestamp: ms } }` |
| 臻识 MQTT | 发布 | `device/{sn}/message/down/set_time` |
| 芊熠 MQTT | 发布 | `{ cmd: "set_time", ... }` |

### 5.3 实现

`DeviceAccessClient.syncTime(deviceSn)` 已定义 → DA Adapter 实现。

**触发时机**：
1. 设备注册上线时
2. 定时任务：每天凌晨 2 点

`DeviceService` 新增 `syncAllDeviceTime()` 定时方法，对全部在线设备逐台校时。

## 6. 改进识别字段存储 P0（0.5天）

### 6.1 目的

接收设备上报的车身颜色、车标、可信度并落库，丰富通行记录数据。

### 6.2 新增字段

`recognition_event_log` 和 `parking_session` 表新增：

```sql
ALTER TABLE recognition_event_log
    ADD COLUMN body_color INT COMMENT '0白-12紫/255未知（臻识编码）',
    ADD COLUMN car_logo VARCHAR(64) COMMENT '车标品牌',
    ADD COLUMN confidence INT COMMENT '识别可信度1-100';

ALTER TABLE parking_session
    ADD COLUMN body_color INT,
    ADD COLUMN body_color_label VARCHAR(16) COMMENT '白色/黑色/...转中文';
```

### 6.3 实现

`DeviceWebhookService.parseRecognitionResult()` 解析臻识 `carColor` / `car_brand.brand` / `confidence` → 落库。

前端通行记录详情展示车身颜色（用色块小圆点）和置信度百分比。

## 实施顺序

| 序号 | 功能 | 依赖 | 建议先行 |
|:---:|------|------|:---:|
| ① | 常开/关闸命令 | 无 | ✅ 最简单 |

> 建议 ①②③ 并行开发，④⑤⑥ 顺序推进。
