## 过度设计项（当前已落地，但超出 MVP 需求）

### 1. Snowflake 分布式主键

| 属性 | 内容 |
|------|------|
| 当前状态 | 全表使用 Snowflake 生成主键 |
| 设计初衷 | "避免自增 ID 跨库冲突"，预留分库分表 |
| 实际场景 | 单库部署，无分库计划，数据量 < 百万级 |
| 引入成本 | ID 长度 19 位，前端显示不友好；时钟回拨风险 |
| 建议动作 | 评估改为 `BIGINT AUTO_INCREMENT`，预留迁移脚本（未来分库时批量改） |
| 预期收益 | 简化代码、减少依赖、ID 可读性提升 |
| 风险 | 已有数据迁移成本；关联表外键需同步修改 |
| 优先级 | P2（二期评估） |
| 负责人 | |

### 2. 三级缓存架构（L1 Caffeine + L2 Redis + L3 MySQL）

| 属性 | 内容 |
|------|------|
| 当前状态 | L1 Caffeine 已启用，5 分钟过期，Redis Pub/Sub 刷新 |
| 设计初衷 | 支撑高并发热点配置读取 |
| 实际场景 | 配置变更频率极低（日级），并发量 < 100 QPS |
| 引入成本 | 缓存一致性复杂度（Pub/Sub 延迟、L1 失效窗口） |
| 建议动作 | 监控 L1 命中率，若低于 80% 则移除，仅保留 Redis 单级 |
| 预期收益 | 减少缓存不一致风险，简化运维 |
| 风险 | 需补充监控指标；移除后需验证性能无退化 |
| 优先级 | P2（联调后监控 2 周决策） |
| 负责人 | |

### 3. Maven 模块粒度偏细

| 属性 | 内容 |
|------|------|
| 当前状态 | 4 层模块：common → framework → system → boot |
| 设计初衷 | 编译期隔离，面向未来微服务拆分 |
| 实际场景 | 运行时仍是单体，模块间通过 Maven 依赖耦合 |
| 引入成本 | 构建复杂度、版本管理开销、跨模块调试成本 |
| 建议动作 | 二期评估：合并为 2 层（common + boot-system），或真拆分独立部署 |
| 预期收益 | 减少维护成本，或获得真隔离 |
| 风险 | 合并时依赖关系梳理；拆分时需引入 RPC/消息 |
| 优先级 | P3（二期架构评审） |
| 负责人 | |

### 4. PWA 离线缓存（booth-web）

| 属性 | 内容 |
|------|------|
| 当前状态 | Service Worker 已配置，离线操作队列设计 |
| 设计初衷 | 岗亭弱网环境下可继续操作 |
| 实际场景 | 岗亭通常固定 PC + 有线网络，弱网场景有限 |
| 引入成本 | 离线冲突处理、数据同步、缓存清理复杂度 |
| 建议动作 | 降级为"乐观 UI + 失败重试"，移除 Service Worker |
| 预期收益 | 减少前端复杂度，避免缓存不一致 |
| 风险 | 极端弱网场景体验下降 |
| 优先级 | P2（联调后评估） |
| 负责人 | |

### 5. RabbitMQ 提前建设

| 属性 | 内容 |
|------|------|
| 当前状态 | 已配置 Exchange/Queue，消费者幂等、死信队列 |
| 设计初衷 | 设备事件异步处理、支付回调解耦 |
| 实际场景 | Device Access v0.2 无真实事件推送，支付未联调 |
| 引入成本 | 运维复杂度、消息堆积监控、消费者异常处理 |
| 建议动作 | 联调阶段先用同步调用 + 异步线程池，真实流量验证后决策是否保留 |
| 预期收益 | 降低运维负担，避免空转 |
| 风险 | 后期切换 MQ 需改造代码 |
| 优先级 | P2（联调后按 QPS 决策） |

## 设计克制项（当前未做，但需记录决策依据）

| 项 | 决策 | 决策依据 | 触发条件 |
|---|------|---------|---------|
| 分库分表 | 暂缓 | 单库数据量 < 百万，复合索引覆盖 99% 查询 | 单表千万级或 QPS > 5000 |
| 微服务拆分 | 暂缓 | 团队规模 2-3 人，无法支撑微服务运维 | 团队 10+ 人或独立部署需求 |
| 分布式事务（Seata/TCC） | 未引入 | 本地消息表 + 最终一致性足够 | 跨服务强一致性场景出现 |
| Kubernetes | 未引入 | Docker Compose 满足当前部署 | 多环境、自动扩缩容需求 |
| 读写分离 | 未引入 | 当前读压力不大，单库索引优化即可 | 读 QPS > 5000 且索引无法优化 |
