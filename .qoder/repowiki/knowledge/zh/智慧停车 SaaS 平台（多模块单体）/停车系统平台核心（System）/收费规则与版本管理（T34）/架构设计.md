本模块遵循标准三层结构：
- Controller 层 `BillingRuleController` 暴露 `/admin/billing-rules` REST API，通过 Sa-Token 的 `@SaCheckPermission("billing:read|write|switch")` 区分读、写、切换三类权限；请求参数使用 Jakarta Validation 校验。
- Service 层 `BillingRuleService` 承载全部业务逻辑，依赖多个 MyBatis-Plus Mapper（`BillingRuleMapper`、`BillingRuleVersionMapper`、`BillingRuleSwitchLogMapper`、`BillingRuleRecalcLogMapper`、`ParkingLotMapper`、`ParkingRecordMapper`）以及 `ParkingLotScopeResolver`（停车场级数据范围）和 `BillingEngine`（重新计算费用），所有写操作以 `@Transactional` 包裹。
- Entity 层 `BillingRule` 为 MyBatis-Plus 实体，映射 `billing_rule` 表，仅包含规则元信息；计费配置（freeMinutes/firstPeriod/unitAmount/dailyCap/maxAmount 等）持久化在独立的 `BillingRuleVersion` 表中，形成「规则主表 + 版本子表」的不可变版本模型。

依赖方向单向：Controller → Service → (Mapper + ScopeResolver + BillingEngine)；租户隔离通过 `DataScope.requireTenantUser()` / `TenantContext.requireTenantId()` 从会话推导，不信任前端传入的 tenantId。
